# 开发调试环境

## 章节目标
补齐高频调试工具链与开发效率环境，使学习者具备持续调试、源码阅读与实验记录能力。

## 适用范围
- 已完成增量开发闭环、需要进行持续调试与问题分析的学习者
- 覆盖日志、串口、版本管理、编辑器四类高频工具
- 不深入性能分析工具（systrace/simpleperf等），这些在 `08-性能与稳定性工程` 章节展开

## 前置条件
- 已完成 `00.5 增量开发与上板调试`，具备增量验证能力
- 设备可通过ADB连接
- 基本的Git使用经验

## 环境/硬件准备
- 编译主机（WSL2或Linux工作站）
- 已部署Android系统的树莓派5
- 网络ADB连接
- USB转串口模块（可选，用于串口调试）
- 串口终端软件（如 `minicom` 或 `picocom`）

## 操作步骤

### 组织编辑器与源码阅读环境

推荐使用 VS Code 通过 Remote-WSL 模式阅读 AOSP 和 Linux Kernel 源码。此架构下，VSCode 本体运行在 Windows 宿主机负责 UI 渲染，VSCode Server 运行在 WSL 中负责文件访问和语言服务，兼顾性能与体验。

#### 在 Windows 宿主机安装 VS Code

访问 [VS Code 官网](https://code.visualstudio.com/) 下载并安装 Windows 版本。安装完成后，在 Windows PowerShell 或 CMD 中验证：

```powershell
code --version
```

#### 在 WSL 中安装 Remote-WSL 扩展

> **注意**：`code` 命令来自 Windows 端的 VS Code，需要通过 Windows PATH 继承才能在 WSL 中使用。如果 WSL 中未配置继承 Windows PATH，需要手动添加。

在 WSL 终端中执行以下命令，确保 `code` 命令可用：

```bash
# 检查 code 是否已在 PATH 中
which code || echo "code 未在 WSL PATH 中，继续添加..."

# 如果未找到，手动添加 VS Code bin 目录到 PATH
# 将 <用户名> 替换为你的 Windows 用户名（可通过 whoami.exe 查看）
export PATH="$PATH:/mnt/c/Users/<用户名>/AppData/Local/Programs/Microsoft VS Code/bin"

# 验证
which code
```

确认 `code` 可用后，安装 Remote-WSL 扩展：

```bash
code --install-extension ms-vscode-remote.remote-wsl
```

安装完成后，再次验证：

```bash
which code
```

输出应为 `/mnt/c/Users/<用户名>/AppData/Local/Programs/Microsoft VS Code/bin/code` 或类似路径。

若希望永久生效，将 PATH 配置写入 `~/.bashrc`：

```bash
echo 'export PATH="$PATH:/mnt/c/Users/<用户名>/AppData/Local/Programs/Microsoft VS Code/bin"' >> ~/.bashrc
```

#### 通过 Remote-WSL 打开 AOSP 源码

在 WSL 终端中执行：

```bash
# 打开 AOSP 源码目录
code /home/lechao/workspace/aosp
```

VS Code 会自动以 Remote-WSL 模式启动，窗口左下角显示绿色的 `WSL: Ubuntu`（或你的发行版名称），表示已连接到 WSL 环境。

#### 安装代码阅读所需的扩展

在 VS Code 中按 `Ctrl+Shift+X` 打开扩展面板，或通过命令行安装：

```bash
# C/C++ 支持（AOSP 和 Kernel 必需）

# Java 支持（AOSP 框架层需要）
code --install-extension redhat.java

# 代码导航增强（可选）

> **注意**：Remote-WSL 模式下，扩展需要安装在 WSL 侧。在扩展面板中，扩展会显示 "Install in WSL: Ubuntu" 按钮，点击安装即可。

    "out": true
  },
  "files.watcherExclude": {
    "out/**": true
  },
  "search.exclude": {
    "out/**": true
  }
}
EOF
```

### 部署 OpenGrok 源码搜索引擎

VS Code 的全局搜索对 AOSP 这种超大型代码库（200GB+、80万+文件）力不从心，OpenGrok 是 Oracle 开源的快速源代码搜索与交叉引用引擎，基于 Apache Lucene 实现高速全文检索，支持定义跳转、交叉引用、版本控制历史浏览，是阅读 AOSP 源码的利器。

> **版本兼容性说明**：OpenGrok 1.13+ 需要 Java 21，当前 WSL 环境为 Java 17，因此使用 **OpenGrok 1.12.7**（兼容 Java 17）。如后续升级 Java 版本，可同步升级 OpenGrok。

#### 安装依赖

```bash
# 安装 Universal ctags（OpenGrok 符号解析必需）
sudo apt update
sudo apt install -y universal-ctags

# 验证
ctags --version
```

#### 创建目录结构

```bash
mkdir -p /home/lechao/opengrok/{data,dist,etc,log}
```

| 目录 | 用途 |
|------|------|
| `dist/` | OpenGrok 程序文件 |
| `data/` | 索引数据（约占源码 30%~50%，即 60~100GB） |
| `etc/` | 配置文件 |
| `log/` | 日志文件 |

#### 下载 OpenGrok

```bash
cd /tmp
curl -L -O https://github.com/oracle/opengrok/releases/download/1.12.7/opengrok-1.12.7.tar.gz
tar -C /home/lechao/opengrok/dist --strip-components=1 -xzf opengrok-1.12.7.tar.gz
```

> **注意**：版本号必须与 Java 版本匹配。Java 17 对应 OpenGrok 1.12.x，Java 21 对应 OpenGrok 1.13+。若版本不匹配会报 `UnsupportedClassVersionError` 错误。

#### 配置 Tomcat 内存

AOSP 级别的索引需要较大的 JVM 堆内存，创建 Tomcat 启动配置：

```bash
sudo tee /usr/share/tomcat10/bin/setenv.sh > /dev/null << 'EOF'

sudo chmod +x /usr/share/tomcat10/bin/setenv.sh
```

> **说明**：`tee` 命令以 root 权限写入文件，`> /dev/null` 隐藏屏幕输出，`<< 'EOF' ... EOF` 是 heredoc 语法将内容传给 tee。整段复制粘贴到终端执行即可。

#### 创建索引脚本

创建 `/home/lechao/opengrok/reindex.sh`：

```bash
cat > /home/lechao/opengrok/reindex.sh << 'EOF'
#!/bin/bash
ulimit -n 65536
java -Xmx16g -server \
  -Djava.util.logging.config.file=/home/lechao/opengrok/etc/logging.properties \
  -jar /home/lechao/opengrok/dist/lib/opengrok.jar \
  -c /usr/bin/ctags \
  -s /home/lechao/workspace/aosp \
  -d /home/lechao/opengrok/data \
  -H -P -S -G -T 6 -m 256 \
  -i d:out -i d:.repo \
  -W /home/lechao/opengrok/etc/configuration.xml \
  -U http://localhost:8080/source
EOF
chmod +x /home/lechao/opengrok/reindex.sh
```

**关键参数说明：**

| 参数 | 值 | 说明 |
|------|-----|------|
| `-Xmx16g` | 16 GB | 索引器 JVM 堆内存，AOSP 级别推荐 16GB |
| `-T 6` | 6 线程 | 索引并行度，建议为 CPU 核数的一半 |
| `-m 256` | 256 MB | Lucene RAM 缓冲区，减少磁盘 IO |
| `-i d:out` | 排除 out 目录 | AOSP 编译输出，无需索引 |
| `-i d:.repo` | 排除 .repo 目录 | repo 工具元数据，无需索引 |
| `-H` | 启用历史 | 生成版本控制历史缓存 |
| `-P` | 启用项目 | 按子目录分项目浏览 |
| `-S` | 搜索 SCM | 自动发现版本控制仓库 |

#### 执行首次索引

```bash
/home/lechao/opengrok/reindex.sh
```

> **注意**：首次索引 AOSP 预计需要 **4~8 小时**（12核/32GB可用内存），索引数据约 60~100GB。后续增量索引约 10~30 分钟。

索引完成后，在 **Windows 宿主机浏览器** 中访问：

```
http://localhost:8080/source
```

WSL2 默认支持 localhost 端口转发，Windows 浏览器可直接访问 WSL 中 Tomcat 的 8080 端口。如遇无法访问，参考下方常见问题。

#### 增量更新索引

当 AOSP 源码有更新后，手动执行重索引：

```bash
/home/lechao/opengrok/reindex.sh
```

OpenGrok 默认启用 `historyBasedReindex`，增量索引时仅处理有变更的文件，无需遍历整个目录树，速度远快于首次索引。

#### OpenGrok 常见问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| `UnsupportedClassVersionError` | OpenGrok 版本与 Java 版本不匹配 | Java 17 使用 OpenGrok 1.12.x，Java 21 使用 1.13+ |
| 首次索引 OOM | JVM 堆内存不足 | 增大 `-Xmx` 参数至 16g 或更高 |
| Windows 浏览器无法访问 localhost:8080 | WSL2 端口转发未生效 | 在 Windows PowerShell（管理员）执行：`netsh interface portproxy add v4tov4 listenport=8080 listenaddress=0.0.0.0 connectport=8080 connectaddress=$(wsl hostname -I)` |
| Tomcat 启动失败 | setenv.sh 权限或路径问题 | 确认 `/usr/share/tomcat10/bin/setenv.sh` 有执行权限 |
| 索引速度极慢 | 未排除 out/.repo 目录 | 确认索引命令包含 `-i d:out -i d:.repo` |
| 搜索结果不完整 | 索引未完成或被中断 | 重新执行 `reindex.sh` |
| 浏览器报错 `Source root path does not exist` | Tomcat 以 `tomcat` 用户运行，源码目录属于当前用户，权限不足 | 见下方"源码目录权限问题"章节 |

**源码目录权限问题**

Tomcat 以 `tomcat` 用户运行，而 AOSP 源码目录 `/home/lechao/workspace/aosp` 属于 `lechao` 用户，默认权限（750）不允许 `tomcat` 用户读取，导致浏览器访问时报错：

```
Source root path "/home/lechao/workspace/aosp" does not exist
```

两种修复方案：

**方案1（推荐）：开放源码目录读权限**

允许其他用户读取源码目录，不影响目录归属：

```bash
chmod o+x /home/lechao
chmod o+x /home/lechao/workspace
chmod -R o+rX /home/lechao/workspace/aosp
```

> **说明**：`o+rX` 表示为其他用户添加读取权限，对目录额外添加执行权限（进入目录必需）。大写 `X` 表示仅对目录和已有执行权限的文件添加执行权限，不会给普通文件加执行位。

**方案2：将 tomcat 用户加入当前用户组**

```bash
sudo usermod -aG lechao tomcat
sudo systemctl restart tomcat10
```

> **说明**：将 `tomcat` 用户加入 `lechao` 组后，`tomcat` 可通过组权限读取源码目录。此方案权限控制更精细，但需要 sudo 权限。

修改权限后，重启 Tomcat 并重新访问：

```bash
sudo systemctl restart tomcat10
```

执行要求：
- Tomcat 正常启动，`sudo systemctl status tomcat10` 显示 active
- 首次索引完成无报错
- Windows 浏览器可访问 `http://localhost:8080/source` 并搜索 AOSP 代码

### 准备串口调试入口

串口是树莓派5上最底层的调试入口，在ADB不可用或设备无法启动时尤为重要。

#### 硬件准备与接线

**所需硬件：**

| 硬件 | 说明 |
|------|------|
| USB转TTL串口模块 | CH340/CH341、CP2102、FT232等，**必须支持3.3V电平** |
| 杜邦线3根 | 母对母 |

> **重要**：树莓派5 GPIO电平为3.3V，串口模块必须设置为3.3V模式。大多数CH340模块上有跳线帽或焊接点可选择3.3V/5V，确保拨到3.3V一侧。**不要连接VCC引脚**，树莓派独立供电，只需接TX、RX、GND三根线。

**接线方式（TX/RX交叉连接）：**

```
USB转TTL模块          树莓派5 GPIO
─────────────        ──────────────
  TXD  ───────────→  RXD  (Pin 10, GPIO15)
  RXD  ←───────────  TXD  (Pin 8,  GPIO14)
  GND  ───────────→  GND  (Pin 6)
```

**树莓派5 GPIO引脚位置（靠近USB-C电源口一侧为Pin 1）：**

```
Pin 1:  3.3V    Pin 2:  5V
Pin 3:  GPIO2   Pin 4:  5V
Pin 5:  GPIO3   Pin 6:  GND  ← 接模块GND
Pin 7:  GPIO4   Pin 8:  GPIO14/TX ← 接模块RX
Pin 9:  GND     Pin 10: GPIO15/RX ← 接模块TX
```

> **注意**：TX/RX必须交叉连接。模块的TX接树莓派的RX，模块的RX接树莓派的TX。如果直连（TX接TX、RX接RX）则无法通信。

#### 启用树莓派5串口输出

树莓派5默认未启用40-pin排针上的UART串口输出，需要同时修改源码中的两个配置文件并重新编译。

> **树莓派5串口架构说明**：
>>
> | 串口设备 | 硬件位置 | 别名 | 用途 |
> |---------|---------|------|------|
> | RP1 UART0 | 40-pin GPIO14/15（Pin 8/10） | `ttyAMA0`、`serial0` | **调试串口，接USB转串口模块** |
> | SoC PL011 | SoC内部，未引出到40-pin | `ttyAMA10`、`serial10` | 系统内置UART，不可用于外部调试 |
> | RP1 UART1~4 | 40-pin其他GPIO | `ttyAMA1`~`ttyAMA4` | 扩展串口 |
> >
> > **关键区别**：树莓派4的 `ttyAMA0` 对应40-pin串口，而树莓派5的 `ttyAMA0` 对应RP1 UART0（40-pin串口），`ttyAMA10` 是SoC内置串口。如果将console配置为 `ttyAMA10`，启动日志不会输出到40-pin排针，导致串口看不到任何输出。

**修改1：`device/brcm/rpi5/boot/config.txt`**

在 `# UART` 注释下添加以下两行：

```txt
# UART
enable_uart=1
dtoverlay=uart0-pi5
```

配置说明：
- `enable_uart=1`：通知固件启用UART，调整核心频率避免波特率偏移
- `dtoverlay=uart0-pi5`：加载RP1 UART0设备树覆盖，启用GPIO14/15上的串口并配置引脚复用

**修改2：`device/brcm/rpi5/BoardConfig.mk`**

将内核命令行中的 `console=ttyAMA10` 改为 `console=ttyAMA0`：

```make
# 修改前
BOARD_KERNEL_CMDLINE := console=ttyAMA10,115200 no_console_suspend root=/dev/ram0 rootwait androidboot.hardware=rpi5

# 修改后
BOARD_KERNEL_CMDLINE := console=ttyAMA0,115200 no_console_suspend root=/dev/ram0 rootwait androidboot.hardware=rpi5
```

> **为什么要改两处**：`config.txt` 中的 `dtoverlay=uart0-pi5` 负责在硬件层面启用RP1 UART0并绑定GPIO14/15引脚，而 `BoardConfig.mk` 中的 `console=ttyAMA0` 负责告诉内核将启动日志输出到RP1 UART0（即40-pin排针）。只改一处都无法在串口上看到启动日志。

> **ttyAMA0 vs ttyAMA10 — 防止配置错误的关键区别**：
>
> 这是树莓派5上**两个完全不同的物理串口**，不可混用：
>
> | | ttyAMA0 | ttyAMA10 |
> |---|---------|----------|
> | 硬件来源 | RP1芯片上的UART0 | BCM2712 SoC内置PL011 |
> | 物理引脚 | **40-pin排针 GPIO14/15（Pin 8/10）** | SoC内部，**未引出到40-pin** |
> | 别名 | `serial0` | `serial10`、`uart10` |
> | 设备树节点 | `/axi/pcie@120000/rp1/serial@30000` | `/soc/serial@7d001000` |
> | 可否用于USB转串口调试 | **可以**（接Pin 6/8/10即可） | **不可以**（物理上接不到） |
>
> **常见错误**：将 `console=ttyAMA10` 配置写入 `BoardConfig.mk`，意图让40-pin串口输出日志。但 ttyAMA10 的物理信号没有连接到40-pin排针，所以USB转串口模块接在Pin 8/10上收不到任何数据。**正确做法是使用 `console=ttyAMA0`**，让内核日志输出到RP1 UART0，这才是40-pin排针上能接收到的串口。
>
> **树莓派4与5的差异**：树莓派4的 `ttyAMA0` 就是40-pin串口，不存在 ttyAMA10。树莓派5因为引入了RP1芯片，串口编号体系发生了变化，新增了 ttyAMA10（SoC内置）和多个RP1 UART。不要照搬树莓派4的串口配置经验。

**重新编译并刷写**：

```bash
cd /home/lechao/workspace/aosp
source build/envsetup.sh
lunch aosp_rpi5-bp1a-userdebug

# 重新编译 boot 镜像（config.txt 和 cmdline.txt 打包在 boot.img 中）
make bootimage systemimage vendorimage -j$(nproc)

# 打包完整刷机镜像
./rpi5-mkimg.sh
```

然后参照 `00.4 刷机与部署` 将新镜像写入SD卡。

> **注意**：`config.txt` 和 `cmdline.txt` 都打包在 `boot.img` 中，修改源码后必须重新编译 `bootimage` 并重新刷写，不能通过修改SD卡上的文件来生效。

#### 主机端串口连接

> **WSL 用户注意**：WSL2 默认无法访问 Windows 上的 USB 串口设备，需要使用 `usbipd-win` 将 USB 设备映射到 WSL 中。详见下方 **4.5 WSL 下映射 USB 串口设备**。

**Linux/WSL环境：**

```bash
# 安装串口终端软件
sudo apt install -y minicom

# 添加串口设备权限（一次性，需重新登录生效）
sudo usermod -aG dialout $USER

# 连接串口（波特率115200）
sudo minicom -D /dev/ttyUSB0 -b 115200
```

或使用picocom：

```bash
sudo apt install -y picocom
sudo picocom -b 115200 /dev/ttyUSB0
```

**关闭minicom硬件流控（重要）：**

minicom默认开启硬件流控，会导致无法接收数据。进入minicom后：

1. 按 `Ctrl+A` 再按 `O` 打开设置
2. 选择 `Serial port setup`
3. 按 `F` 将 `Hardware Flow Control` 设为 `No`
4. 按回车保存，再按 `Esc` 退出设置

**Windows原生环境：**

使用PuTTY或MobaXterm：
- 连接类型：Serial
- 端口：COM3（设备管理器中查看实际端口号）
- 波特率：115200
- 数据位：8，停止位：1，无校验，无流控

#### 验证串口连接

1. 先连接串口线，再给树莓派上电
2. 串口终端应能看到启动日志输出
3. 启动完成后，按回车键，应出现shell提示符

如果Android已启动到图形界面，串口可能需要获取root权限：

```bash
# 在串口终端中执行
su
```

**通过串口连接WiFi：**

串口连接成功后，可以通过命令行连接WiFi网络：

```bash
# 启用WiFi
svc wifi enable

# 连接WPA2网络（Android 12+推荐方式）
cmd wifi connect-network "HUAWEI-BE7P" wpa2 "meiyoumima"

# 确认连接状态
cmd wifi status

# 查看获取的IP地址
ip addr show wlan0
```

> **注意**：`wpa_cli` 在Android中不可用，WiFi管理走Framework层，需使用 `cmd wifi` 命令。如果 `cmd wifi` 不可用，可在屏幕UI中操作：Settings → Network & Internet → WiFi → 选择网络连接。

**通过串口开启网络ADB：**

WiFi连接成功后，开启网络ADB以便主机通过ADB连接：

```bash
# 开启网络ADB
setprop service.adb.tcp.port 5555 && stop adbd && start adbd

# 确认adbd已启动
getprop init.svc.adbd
```

然后在主机端连接：

```bash
adb connect <树莓派IP>:5555
adb devices
```

> **建议**：串口适合首次调试和排查问题，日常开发推荐使用网络ADB，传输速度更快、操作更便捷。

**保存串口日志：**

```bash

```

#### WSL 下映射 USB 串口设备

WSL2 不支持直接访问 Windows 上的 USB 设备，需要通过 `usbipd-win` 工具将 USB 设备映射到 WSL 中。

**步骤 1：在 Windows 端安装 usbipd-win**

在 **Windows PowerShell（管理员）** 中执行：

```powershell
winget install usbipd
```

或从 [GitHub Release](https://github.com/dorssel/usbipd-win/releases) 下载安装包。

**步骤 2：确认 USB 串口设备**

在 **Windows PowerShell（管理员）** 中执行：

```powershell
usbipd list
```

输出示例：

```
Connected:
BUSID  DEVICE                                                        STATE
1-2    USB Serial Device                                             Not shared
1-3    Logitech USB Input Device                                     Not shared
```

找到 USB 转串口模块对应的 BUSID（如 `1-2`）。

**步骤 3：共享并附加 USB 设备到 WSL**

在 **Windows PowerShell（管理员）** 中执行：

```powershell
# 共享设备（首次需要）
usbipd bind --busid 1-2

# 附加设备到 WSL
usbipd attach --wsl --busid 1-2
```

**步骤 4：在 WSL 中确认设备**

```bash
# 检查 USB 设备是否出现
lsusb

# 检查串口设备节点
ls /dev/ttyUSB*

# 加载 USB 串口驱动（如设备未自动识别）
sudo modprobe ftdi_sio
sudo modprobe cp210x
sudo modprobe ch341
```

> **注意**：常见的 USB 转串口芯片有 CH340/CH341、CP2102、FT232 等，根据你的模块加载对应驱动。

**步骤 5：添加串口设备权限**

```bash
# 将当前用户加入 dialout 组，避免每次使用 sudo
sudo usermod -aG dialout $USER

# 重新登录 WSL 使权限生效
exit
# 重新进入 WSL 后验证
groups
```

**步骤 6：每次使用前重新附加**

WSL 重启后 USB 设备映射会丢失，需要重新在 Windows PowerShell 中执行：

```powershell
usbipd attach --wsl --busid 1-2
```

常见问题：

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| `usbipd` 命令未找到 | 未安装 usbipd-win | 执行 `winget install usbipd` 安装 |
| `usbipd attach` 报错 | 设备未共享或 WSL 未运行 | 先执行 `usbipd bind --busid X`，确认 WSL 正在运行 |
| WSL 中 `ls /dev/ttyUSB*` 无设备 | 驱动未加载或设备未附加 | 执行 `sudo modprobe` 加载驱动，重新执行 `usbipd attach` |
| 串口权限不足 | 当前用户不在 dialout 组 | 执行 `sudo usermod -aG dialout $USER` 并重新登录 |

#### 串口调试常见问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 串口无输出 | TX/RX未交叉连接 | 模块TX接树莓派RX，模块RX接树莓派TX |
| 串口无输出 | 串口未在config.txt启用 | 添加 `enable_uart=1` |
| 串口无输出 | cmdline.txt未配置console | 编译时确保 `BoardConfig.mk` 中有 `console=ttyAMA0,115200` |
| 串口无输出 | minicom硬件流控开启 | 关闭硬件流控：Ctrl+A→O→F设为No |
| 串口乱码 | 波特率不对 | 确认波特率为115200 |
| 串口乱码 | 电平不匹配 | 确认串口模块设置为3.3V而非5V |
| WSL中无ttyUSB设备 | USB设备未映射 | 重新执行 `usbipd attach --wsl --busid X` |
| WSL中无ttyUSB设备 | 驱动未加载 | 执行 `sudo modprobe ch341` 或对应驱动 |

执行要求：
- 串口连接后能看到设备启动日志输出
- 能通过串口获取root shell
- 能保存串口日志到文件

## 常见问题与排查
- **VS Code 左下角未显示 WSL 标识**：确认已安装 Remote-WSL 扩展；尝试在 WSL 终端中用 `code .` 命令启动，而非从 Windows 开始菜单打开
- **WSL 中 `code` 命令未找到**：在 WSL 终端中执行 `code .`，VS Code 会自动将 `code` 命令添加到 WSL 的 PATH 中；若仍不可用，手动添加：`echo 'export PATH="$PATH:/mnt/c/Users/<用户名>/AppData/Local/Programs/Microsoft VS Code/bin"' >> ~/.bashrc && source ~/.bashrc`
- **扩展未在 WSL 侧安装**：Remote-WSL 模式下扩展需单独安装在 WSL 侧，在扩展面板中点击 "Install in WSL: Ubuntu" 按钮
- **VS Code 打开 AOSP 源码卡顿**：排除 `out/` 目录，避免索引构建产物；确认 `.vscode/settings.json` 中已配置 `files.exclude`、`files.watcherExclude`、`search.exclude`
- **C/C++ 智能提示不准确**：确认 `c_cpp_properties.json` 中 `compilerPath` 指向正确的 Clang 工具链路径；Kernel 项目需设置 `__KERNEL__` 和 `CONFIG_ARM64` 宏定义
- **logcat输出过多无法定位问题**：使用 `-s` 按标签过滤，或使用 `grep` 按关键字过滤，不要在大量日志中盲目搜索
- **串口无输出**：确认TX/RX交叉连接（模块TX接树莓派RX），确认源码中 `config.txt` 有 `enable_uart=1` 和 `dtoverlay=uart0-pi5`，确认 `BoardConfig.mk` 中有 `console=ttyAMA0,115200`，确认已重新编译并刷写 `boot.img`，关闭minicom硬件流控
- **git diff输出过多**：指定文件路径查看单个文件变更，如 `git diff <file_path>`
- **别名不生效**：确认已执行 `source ~/.bashrc`，确认别名写入的是当前用户的配置文件
