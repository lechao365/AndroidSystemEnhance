# WSL2环境搭建

## 章节目标
在 Windows 主机上完成 WSL2 + Ubuntu 的最小可用开发环境搭建，确保后续 Android 源码下载、构建、调试相关章节有统一起点。

## 适用范围
- 宿主机为 Windows 10/11
- 学习路径以 Windows + WSL2 为主，不要求额外 Linux 物理机
- 用于后续源码目录规划、AOSP 构建前准备、ADB 调试工具接入

## 前置条件
- 已具备 Windows 管理员权限
- 了解基础终端命令与文件路径概念
- 建议提前确认公司网络、校园网或家庭网络是否需要代理
- 建议预留至少 200GB 可用磁盘空间，内存建议 16GB 起步
- 如主机内存充足（如 64GB），建议为 WSL2 分配 32-48GB 内存以加速 AOSP 编译

## 环境/硬件准备
- Windows 10 21H2 及以上，或 Windows 11
- SSD 优先，不建议把大体量源码长期放在机械硬盘或 Windows 挂载盘
- 稳定网络环境，可访问常用软件源
- 如需真机调试，准备可连接的 Android 设备与数据线
- 建议提前规划后续源码目录，例如 `~/workspace/aosp`

## 操作步骤

### 1. 启用 WSL2 并安装 Ubuntu
在 Windows PowerShell 中以管理员身份执行：

```bash
wsl --install
```

执行完成后重启系统，首次进入 Ubuntu 时完成用户名与密码初始化。初始化后可用以下命令确认发行版状态：

```bash
wsl -l -v
```

执行要求：
- 默认版本为 WSL2
- Ubuntu 可正常启动并进入 shell
- 后续所有 Android 开发操作尽量在 Ubuntu 内完成

### 2. 更新基础包并安装常用依赖
进入 Ubuntu 后，先更新软件源并安装最小依赖集：

```bash
sudo apt update
sudo apt install -y git curl python3 python3-pip unzip zip adb openjdk-17-jdk repo
```

建议同步执行基础清理，避免旧缓存长期占用空间：

```bash
sudo apt autoremove -y
sudo apt clean
```

执行要求：
- `apt update` 无明显源错误
- 基础工具安装完成后再进入后续章节
- 如果网络较慢，先确认镜像源与代理策略，不要重复中断安装

### 3. 配置 shell / git / python / adb / repo
先确认核心工具可用：

```bash
python3 --version
git --version
adb version
java -version
repo --help
```

再完成最小 git 身份配置：

```bash
git config --global user.name "你的姓名"
git config --global user.email "你的邮箱"
git config --global core.autocrlf input
```

#### 配置 GitHub SSH 密钥

为避免每次推送代码时输入密码，建议配置 SSH 密钥认证：

**1. 生成 SSH 密钥**

在 WSL 中执行：

```bash
ssh-keygen -t ed25519 -C "你的GitHub邮箱"
# 一路回车使用默认设置即可
```

**2. 查看并复制公钥**

```bash
cat ~/.ssh/id_ed25519.pub
```

**3. 添加到 GitHub**

1. 打开 GitHub → Settings → SSH and GPG keys → New SSH key
2. 粘贴公钥内容，保存

**4. 验证连接**

```bash
ssh -T git@github.com
# 成功会显示：Hi xxx! You've successfully authenticated...
```

**5. 修改仓库远程地址为 SSH**

如果仓库当前使用 HTTPS 地址，需改为 SSH：

```bash
git remote set-url origin git@github.com:用户名/仓库名.git
```

**注意事项**：
- 如果在 Windows PowerShell 中生成了密钥，WSL 默认无法访问，需复制到 WSL：
  ```bash
  cp /mnt/c/Users/你的用户名/.ssh/id_ed25519 ~/.ssh/
  cp /mnt/c/Users/你的用户名/.ssh/id_ed25519.pub ~/.ssh/
  chmod 600 ~/.ssh/id_ed25519
  chmod 644 ~/.ssh/id_ed25519.pub
  ```
- 代理问题：如果 `git push` 报 `Failed to connect via 127.0.0.1`，说明 Git 配置了代理但代理未运行，执行以下命令清除：
  ```bash
  git config --global --unset http.proxy
  git config --global --unset https.proxy
  ```

建议保留 WSL 默认 bash 作为主 shell，并把常用别名或环境变量统一写入 `~/.bashrc`。如需立即生效：

```bash
source ~/.bashrc
```

执行要求：
- shell 可正常打开并加载用户配置
- git 具备最小身份配置
- python、adb、java、repo 至少能被系统识别

### 4. 规划源码目录、磁盘空间与交换分区
源码目录建议放在 Linux 文件系统中，不要直接放在 `/mnt/c`、`/mnt/d` 等 Windows 挂载盘，以避免大量小文件场景下的性能损失。

建议执行：

```bash
mkdir -p ~/workspace/aosp
cd ~/workspace/aosp
pwd
df -h
free -h
swapon --show
```

执行要求：
- 后续源码目录可创建、可进入、可写入
- `df -h` 能看到剩余磁盘空间，优先确保构建盘空间充足
- `free -h` 与 `swapon --show` 可用于判断内存与交换分区是否满足后续构建需要
- 如果交换分区过小或不可用，优先在 Windows 侧调整 WSL 资源配置后再继续

#### 调整 WSL2 内存与交换分区配置

AOSP 编译是内存密集型任务，WSL2 默认只分配宿主机一半内存，可能不满足编译需求。如主机内存充足（如 64GB），建议通过 `.wslconfig` 手动分配更多内存。

在 Windows 用户目录下创建或编辑 `C:\Users\<用户名>\.wslconfig`：

```ini
[wsl2]
memory=48GB
swap=0
localhostForwarding=true
```

配置说明：
- `memory`：为 WSL2 分配的内存上限，建议 32-48GB，根据宿主机总内存和日常负载调整
- `swap=0`：禁用 WSL2 内部虚拟交换文件，避免与系统 swap 分区重复开销
- `localhostForwarding=true`：允许通过 localhost 访问 WSL2 内的服务

修改后需在 PowerShell 中重启 WSL 使配置生效：

```powershell
wsl --shutdown
```

重新进入 WSL 后，用 `free -h` 验证内存是否已调整到预期值。

### 5. 配置代理与网络连通性（按需）
仅在当前网络访问软件源、代码仓或外部依赖失败时再配置代理。常见做法是在当前 shell 中临时导出环境变量：

```bash
export http_proxy=http://127.0.0.1:7890
export https_proxy=http://127.0.0.1:7890
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
```

可用以下命令验证网络连通性：

```bash
curl -I https://www.google.com
curl -I https://android.googlesource.com
```

执行要求：
- 仅在需要时启用代理，避免把问题复杂化
- 代理配置应能被当前 shell 感知
- 网络可访问后再进行源码同步或依赖下载

### 6. 验证开发环境可用性
按顺序执行最小验证：

```bash
python3 --version
git --version
adb version
java -version
mkdir -p ~/workspace/aosp && cd ~/workspace/aosp && pwd
df -h
free -h
```

如果后续需要连接设备，再补充：

```bash
adb devices
```

执行要求：
- 版本命令均可返回结果
- 源码目录可正常访问
- 资源状态满足进入后续源码下载与构建章节的最低要求

## 验证方法
按以下标准逐项检查：
- `python3 --version` 可正常输出版本
- `git --version`、`adb version`、`java -version` 可执行
- 可以在 WSL2 中创建并访问后续源码目录，例如 `~/workspace/aosp`
- `df -h` 与 `free -h` 显示资源满足后续构建需要

建议把以下信息记录到自己的学习笔记中：
- Ubuntu 版本
- JDK 版本
- 源码目录位置
- 当前磁盘剩余空间与内存情况
- 是否启用了代理

## 常见问题与排查
- **WSL2 无法启动**：先检查 Windows 功能中的 WSL 与虚拟化平台是否启用，再确认系统是否已重启，必要时重新执行 `wsl -l -v` 与 `wsl --status` 查看状态。
- **`adb` 无法连接设备**：先确认 USB 线、设备开发者选项、USB 调试授权是否正常，再执行 `adb devices` 查看设备列表；如走网络调试，先确认主机与设备网络互通。
- **编译前磁盘不足**：优先检查 `df -h`，清理 `apt` 缓存、历史下载目录和无用构建产物；不要把大体量源码直接放在 Windows 挂载盘中。
- **代理导致下载失败**：先用 `curl` 验证目标地址是否可访问，再检查 `http_proxy`、`https_proxy` 是否生效；如果代理异常，先取消代理后重试基础命令。
