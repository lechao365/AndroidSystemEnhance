# 刷机与部署

## 章节目标
将构建产物稳定部署到树莓派5，完成首次启动验证，建立"编译-部署-运行"闭环。

## 适用范围
- 已完成AOSP构建并拥有镜像产物的学习者
- 以树莓派5为部署目标，使用SD卡作为部署介质
- 不涉及fastboot刷机、安全启动验证等商业设备专用流程

## 前置条件
- 已完成 `00.3 Android系统构建`，构建产物可用
- 已完成 `00.2 树莓派5硬件认知`，了解硬件接口位置
- 准备好SD卡（建议32GB+，Class 10或更高）与读卡器
- 了解Linux分区与文件系统基础概念

## 环境/硬件准备
- 树莓派5主板及电源
- SD卡与USB读卡器
- Micro HDMI线与显示器
- USB键盘
- 网线（可选，用于网络ADB）
- 编译主机（WSL2或Linux工作站）

## 操作步骤

### 确认构建产物与目标介质
确认构建产物存在：

```bash
ls out/target/product/rpi5/
```

关键产物说明：

| 产物 | 用途 |
|------|------|
| `RaspberryVanillaAOSP15-*-rpi5.img` | 树莓派5完整刷机镜像（由 `rpi5-mkimg.sh` 生成） |
| `boot.img` | 启动分区镜像（含kernel与ramdisk） |
| `system.img` | 系统分区镜像 |
| `vendor.img` | 厂商分区镜像 |
| `ramdisk.img` | 内存盘镜像 |

> **注意**：如果执行过 `rpi5-mkimg.sh`，产物目录下会出现 `RaspberryVanillaAOSP15-<日期>-rpi5.img` 完整刷机镜像；如果未执行该脚本，则只有 `boot.img`、`system.img`、`vendor.img` 等分区镜像。刷机时优先使用完整镜像。

执行要求：
- 构建产物目录下存在完整刷机镜像（`RaspberryVanillaAOSP15-*-rpi5.img`）或 `boot.img`、`system.img` 等关键分区镜像
- 明确后续刷机使用哪个镜像文件

### WSL 环境下写入镜像到 TF 卡（WSL 用户必读）

> **背景**：WSL2 默认无法直接访问 Windows 上插入的 USB 设备（包括 TF 卡读卡器）。微软官方明确说明：`wsl --mount` **不支持 USB 读卡器/SD 卡/Flash 盘**，仅支持可被 Windows 识别为可附加物理磁盘的块设备。因此，WSL 用户应使用 **Windows 刷卡工具** 完成镜像写入。

#### 确认构建产物并复制到 Windows

在 **WSL** 中确认镜像文件存在：

```bash
ls out/target/product/rpi5/RaspberryVanillaAOSP15-*-rpi5.img
```

将镜像复制到 Windows 可访问的目录（以 `/mnt/c/Files/RaspberryImages/` 为例）：

```bash
# 创建目标目录（如果不存在）
mkdir -p /mnt/c/Files/RaspberryImages/

# 复制镜像文件
cp out/target/product/rpi5/RaspberryVanillaAOSP15-*-rpi5.img /mnt/c/Files/RaspberryImages/
```

> **说明**：`/mnt/c/` 对应 Windows 的 `C:\` 盘。上述路径对应 `C:\Files\RaspberryImages\`。如你的 Windows 盘符或目录不同，请按实际情况调整。

确认复制完成：

```bash
ls -lh /mnt/c/Files/RaspberryImages/RaspberryVanillaAOSP15-*-rpi5.img
```

#### 在 Windows 中安装刷卡工具

推荐使用以下任一工具：

| 工具 | 下载地址 | 特点 |
|------|---------|------|
| **Raspberry Pi Imager** | https://www.raspberrypi.com/software/ | 官方工具，界面简洁，支持自定义镜像 |
| **balenaEtcher** | https://etcher.balena.io/ | 跨平台，自动校验，防写错盘 |

下载并安装其中之一即可。

#### 使用刷卡工具写入镜像

**步骤 1：插入 TF 卡**

将 TF 卡插入 USB 读卡器，连接到 Windows 主机。

**步骤 2：确认磁盘号（可选，用于核对）**

在 **Windows PowerShell（管理员）** 中执行：

```powershell
Get-Disk | Select-Object Number, FriendlyName, Size
```

输出示例：

```
Number FriendlyName                   Size
------ ------------                   ----
     1 ZHITAI TiPlus7100 1TB 1024209543168
     0 WDC WD10EZEX-08WN4A0  1000204886016
     2 Mass Storage Device    128177930240
```

根据容量和名称找到 TF 卡对应的磁盘号（如上例中 `Number 2` 为 128GB 的 TF 卡）。

> **警告**：务必根据容量和设备名称准确识别 TF 卡磁盘号，选错磁盘会导致 Windows 系统盘数据被覆盖！

**步骤 3：使用工具写入镜像**

**使用 Raspberry Pi Imager：**

1. 打开 Raspberry Pi Imager
2. 点击 **"Choose OS"** → 选择 **"Use custom"**
3. 浏览并选择 `C:\Files\RaspberryImages\RaspberryVanillaAOSP15-<日期>-rpi5.img`
4. 点击 **"Choose Storage"** → 选择 TF 卡对应的磁盘
5. 点击 **"Write"** 开始写入
6. 等待写入完成（约 10-30 分钟，取决于镜像大小和卡速度）

**使用 balenaEtcher：**

1. 打开 balenaEtcher
2. 点击 **"Flash from file"** → 选择 `C:\Files\RaspberryImages\RaspberryVanillaAOSP15-<日期>-rpi5.img`
3. 点击 **"Select target"** → 选择 TF 卡对应的磁盘
4. 点击 **"Flash!"** 开始写入
5. 等待写入和校验完成

> **注意**：写入过程中不要拔出 TF 卡或关闭程序。写入完成后工具会自动校验数据完整性。

#### 写入完成后清理

写入完成后，可以删除 Windows 临时目录中的镜像文件以节省空间：

```powershell
Remove-Item C:\Files\RaspberryImages\RaspberryVanillaAOSP15-*-rpi5.img
```

安全移除 TF 卡：

1. 在 Windows 任务栏右下角点击 **"安全删除硬件并弹出媒体"** 图标
2. 选择 TF 卡对应的设备
3. 等待提示 **"可以安全移除"** 后拔出 TF 卡

#### WSL 刷卡常见问题

| 问题 | 原因 | 解决方法 |
|------|------|---------|
| 镜像文件复制失败 | Windows 盘符未挂载到 WSL | 检查 `/mnt/c/Files/RaspberryImages/` 路径是否存在，或使用其他盘符 |
| 刷卡工具无法识别 TF 卡 | 读卡器驱动问题或 TF 卡损坏 | 更换读卡器或 TF 卡，检查 Windows 磁盘管理是否可见 |
| 写入速度极慢 | TF 卡质量差或读卡器 USB 2.0 | 使用 Class 10 或更高速度的 TF 卡，使用 USB 3.0 读卡器 |
| 写入后 TF 卡无法启动 | 镜像文件损坏或写入不完整 | 重新下载或构建镜像，使用校验功能确认写入完整 |
| 刷卡工具报错"无法写入" | TF 卡被写保护或磁盘已挂载 | 检查 TF 卡写保护开关，关闭其他访问该磁盘的程序 |

执行要求：
- 镜像文件已成功复制到 Windows 可访问目录
- 已使用刷卡工具完成镜像写入
- 写入过程无报错，校验通过

### 首次上电启动与基础观察
将SD卡插入树莓派5，连接显示器和键盘，最后连接电源。

观察启动过程：
1. 红色电源指示灯常亮 → 供电正常
2. 绿色活动指示灯闪烁 → 正在读取SD卡
3. 显示器出现启动画面或命令行输出 → 显示输出正常
4. 出现Android桌面或Launcher → 系统启动完成

如果接有串口模块，可同步观察串口启动日志。

执行要求：
- 设备能完成启动，不停留在明显异常状态
- 至少有一种输出可观察（显示器或串口）

### 确认 Windows 侧 ADB 可用（可选）

> **说明**：`adb` 已在 `00.1 WSL2环境搭建` 中安装。若你需要在 Windows 端直接执行 ADB 命令，只需额外确认 Windows 侧也具备 `adb`。

最小检查方式：

```powershell
adb version
```

若命令不存在，可任选一种方式补齐：
- 使用 Chocolatey：`choco install adb -y`
- 手动安装 Android SDK Platform Tools，并将其加入 Windows `PATH`

详细调试命令与使用方式见 `00.6 开发调试环境`。

执行要求：
- 至少确认一个常用操作环境（WSL 或 Windows）中的 `adb` 可正常执行
- 知道后续主要使用网络ADB连接树莓派5

### 建立网络ADB连接入口

树莓派5没有 USB OTG 设备口，**USB ADB 不可用**，需通过**网络ADB**或**串口辅助**建立调试连接。

> **详细串口接线、WiFi连接和网络ADB步骤见 `00.6 开发调试环境` 第4节**。

首次启动后若 ADB 无法连接，可按以下最小流程处理：

1. 通过串口进入设备 shell
2. 连接 WiFi：`cmd wifi connect-network "WiFi名称" wpa2 "WiFi密码"`
3. 开启网络ADB：`setprop service.adb.tcp.port 5555 && stop adbd && start adbd`
4. 主机端连接：`adb connect <设备IP>:5555`

连接后可执行：

```bash
adb devices
adb shell
adb root
adb remount
```

执行要求：
- `adb devices` 能列出设备
- `adb shell` 能进入设备命令行
- `adb root` 能获取root权限（userdebug版本）

## 验证方法
- 设备能完成启动不停留在明显异常状态
- 至少有一种可用的交互或调试入口（显示/ADB/串口三者之一）
- 能记录本次使用的镜像版本、介质和启动结果
- `adb devices` 能识别到设备（如已建立ADB连接）

## 常见问题与排查
- **WSL 中镜像复制到 Windows 失败**：检查 WSL 中 `/mnt/c/Files/RaspberryImages/` 路径是否可访问，确认 Windows 盘符已正确挂载到 WSL
- **刷卡工具无法识别 TF 卡**：检查读卡器驱动是否正常，在 Windows 磁盘管理中确认 TF 卡可见，尝试更换读卡器或 USB 口
- **刷卡工具写入速度极慢**：使用 Class 10 或更高速度的 TF 卡，使用 USB 3.0 接口的读卡器
- **`wsl --mount` 报错 `0x8007000f`**：`wsl --mount` 不支持 USB 读卡器/SD 卡/Flash 盘，这是微软已知限制，请使用步骤 2 中的 Windows 刷卡工具方案
- **上电后无任何显示**：检查HDMI线是否连接到HDMI0口，确认SD卡镜像写入正确，尝试重新写入镜像
- **启动卡在Logo或黑屏**：通过串口查看启动日志，定位卡住阶段（kernel panic、驱动加载失败、init卡住）
- **ADB无法连接**：树莓派5无USB OTG，需使用网络ADB；通过串口连接WiFi后执行 `setprop service.adb.tcp.port 5555` 开启网络ADB
- **串口无输出**：确认源码中 `config.txt` 有 `enable_uart=1` 和 `dtoverlay=uart0-pi5`，确认 `BoardConfig.mk` 中有 `console=ttyAMA0,115200`，确认已重新编译并刷写，TX/RX交叉连接
- **串口中wpa_cli不可用**：Android WiFi管理走Framework层，使用 `cmd wifi connect-network` 命令连接WiFi
- **SD卡写入后无法启动**：确认镜像文件完整（校验sha256），确认写入过程无报错且校验通过，确认SD卡无硬件故障
- **启动后功能异常（WiFi/蓝牙不可用等）**：raspberry-vanilla 项目已知 SELinux 为 permissive 模式、不支持 userdata 加密，部分功能可能需要额外配置，记录问题并留待后续章节处理
