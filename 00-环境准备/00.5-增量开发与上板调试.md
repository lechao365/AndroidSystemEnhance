# 增量开发与上板调试

## 章节目标
建立"改一点、编一点、替一点、验一点"的最小增量闭环，避免每次都全量重刷，并能快速回退。

## 适用范围
- 已完成刷机部署、设备可正常启动的学习者
- 需要进行模块级修改与验证的场景
- 不展开模块依赖图、Soong规则机制，这些在 `01-构建系统` 章节深入

## 前置条件
- 已完成 `00.4 刷机与部署`，设备可正常启动
- 已建立网络ADB连接
- 了解基本的Linux命令行操作

## 环境/硬件准备
- 已部署Android系统的树莓派5
- 编译主机与设备之间的ADB连接
- 源码目录完整，构建环境已初始化

## 操作步骤

### 增量编译提速技巧

首次全量编译后，后续增量编译可大幅缩短时间。以下是常用提速方法：

**1.1 模块级编译（最快）**

只编译修改的单个模块，不重新构建依赖：

```bash
m <module_name>          # 编译指定模块
mm                       # 编译当前目录下的模块
mmm <path>               # 编译指定路径下的模块
```

示例：
```bash
m framework-res          # 只编译 framework-res
mmm frameworks/base      # 编译 frameworks/base 下所有模块
```

**1.2 按需编译镜像**

根据修改范围选择编译目标：

| 修改内容 | 编译命令 | 耗时参考 |
|---------|---------|---------|
| kernel / ramdisk / init | `make bootimage` | 1~5 分钟 |
| 框架层 / 系统应用 | `make systemimage` | 5~30 分钟 |
| 厂商模块 / HAL | `make vendorimage` | 1~10 分钟 |
| 多个分区变更 | `make droid` | 自动增量编译 |

```bash
make bootimage -j$(nproc)      # 只编译 boot
make systemimage -j$(nproc)    # 只编译 system
make vendorimage -j$(nproc)    # 只编译 vendor
make droid -j$(nproc)          # 增量编译所有变更
```

**1.3 保持构建产物**

- 不要执行 `make clean` 或 `make clobber`，保留 `out/` 目录
- 增量编译会自动检测变更，只重新编译受影响的部分
- 如需彻底清理，可单独清理模块：`m clean-<module_name>`

**1.4 常用增量编译场景对照**

| 场景 | 推荐命令 |
|-----|---------|
| 修改单个模块 | `m <module_name>` |
| 修改当前目录模块 | `mm` |
| 修改 kernel / init | `make bootimage` |
| 修改 framework | `make systemimage` |
| 修改 HAL / 驱动 | `make vendorimage` |
| 不确定影响范围 | `make droid` |
| 打包完整镜像 | `/home/lechao/workspace/aosp/rpi5-mkimg.sh` |

执行要求：
- 理解模块级编译与镜像级编译的区别
- 知道根据修改范围选择合适的编译命令

### 禁用 dm-verity（增量开发前置条件）

> **背景**：Android 默认启用 dm-verity（验证启动），会校验 system/vendor 等分区完整性。启用时，`adb remount` 会报错 "Device must be bootloader unlocked"，无法推送修改后的文件到系统分区。树莓派5没有传统 bootloader 锁定机制，需要从构建层面禁用 dm-verity。

**2.1 应用patch P1和P2**

 应用以下 patch（P1/P2 的完整说明见下方；`00.7 当前章节patch` 文档待创建）：

- **P1：禁用dm-verity** — 包含两步：
  - 步骤1：修改 `device/brcm/rpi5/BoardConfig.mk` 的 `BOARD_KERNEL_CMDLINE`，添加 `androidboot.verifiedbootstate=orange`（解决 `ro.boot.verifiedbootstate` 属性为空导致 remount 检查失败的问题）
  - 步骤2：修改 `device/brcm/rpi5/BoardConfig.mk`，添加 `BOARD_BUILD_DISABLED_VBMETAIMAGE := true`
- **P2：启用串口控制台** — 修改 `device/brcm/rpi5/boot/config.txt`，添加 `enable_uart=1` 和 `dtoverlay=uart0-pi5`；修改 `device/brcm/rpi5/BoardConfig.mk`，将 `console=ttyAMA10` 改为 `console=ttyAMA0`

> 也可使用一键应用脚本：`/home/lechao/workspace/aosp/apply_patches.sh`（脚本需用户自行创建，内容为上述 P1/P2 的自动化版本）

**2.2 增量编译受影响的镜像**

修改 BoardConfig.mk 和 config.txt 后，需要重新编译受影响的镜像：

```bash
cd /home/lechao/workspace/aosp
source /home/lechao/workspace/aosp/build/envsetup.sh
lunch aosp_rpi5-bp1a-userdebug

# 重新编译 boot 镜像（包含 config.txt 和 cmdline.txt）以及 system/vendor 镜像
make bootimage systemimage vendorimage -j$(nproc)
```

**2.3 重新打包完整镜像**

```bash
/home/lechao/workspace/aosp/rpi5-mkimg.sh
```

**2.4 重新刷写 SD 卡**

参照 `00.4 刷机与部署` 的步骤，将新生成的完整镜像写入 SD 卡：

```bash
# 确认新镜像已生成
ls -lh /home/lechao/workspace/aosp/out/target/product/rpi5/RaspberryVanillaAOSP15-*-rpi5.img

# 复制到 Windows 可访问目录
cp /home/lechao/workspace/aosp/out/target/product/rpi5/RaspberryVanillaAOSP15-*-rpi5.img /mnt/c/Files/RaspberryImages/
```

然后使用 Raspberry Pi Imager 或 balenaEtcher 写入 SD 卡（详见 `00.4` 第2步）。

**2.5 最小化编译与单独刷写 boot 分区（可选）**

> **适用场景**：仅修改了 `config.txt`、`cmdline.txt` 或内核配置，无需重新编译 system/vendor 镜像，可单独刷写 boot 分区，大幅缩短验证周期。

**步骤 1：只编译 boot 镜像**

```bash
cd /home/lechao/workspace/aosp
source build/envsetup.sh
lunch aosp_rpi5-bp1a-userdebug

# 仅编译 boot 镜像（约 1-3 分钟）
make bootimage -j$(nproc)
```

**步骤 2：单独刷写 boot 分区**

方式一：通过 ADB 刷写（设备已启动且 ADB 可连接）

```bash
adb root
adb remount

# 推送 boot.img 到设备
adb push out/target/product/rpi5/boot.img /sdcard/

# 写入 boot 分区（树莓派5的 boot 分区是 mmcblk0p1）
adb shell dd if=/sdcard/boot.img of=/dev/block/mmcblk0p1 bs=4M

# 重启验证
adb reboot
```

方式二：直接写入 SD 卡（设备未启动，SD 卡插入电脑）

```bash
# 确认 SD 卡设备路径（Linux/WSL）
lsblk

# 写入 boot 分区（假设 SD 卡是 /dev/sdX，boot 分区是第一个分区 sdX1）
sudo dd if=out/target/product/rpi5/boot.img of=/dev/sdX1 bs=4M status=progress conv=fsync
sync

# 安全移除 SD 卡后插入树莓派启动
sudo eject /dev/sdX
```

方式三：Windows 环境下写入 boot 分区

1. 将 `boot.img` 复制到 Windows：
   ```bash
   cp out/target/product/rpi5/boot.img /mnt/c/Files/RaspberryImages/
   ```

2. 使用工具写入 boot 分区：
   - **Raspberry Pi Imager**：选择 `boot.img` → 选择 SD 卡 → 勾选 "No verification" → Write
   - **balenaEtcher**：选择 `boot.img` → 选择 SD 卡 → Flash（注意会覆盖整个 SD 卡，不推荐）
   - **Win32DiskImager**：选择 `boot.img` → 选择 SD 卡盘符（boot 分区） → Write

> **注意**：Windows 下直接写入 boot 分区需要确保只写入第一个分区（boot 分区），避免覆盖整个 SD 卡。推荐使用 Linux/WSL 方式或 ADB 方式。

**步骤 3：验证串口输出**

重启后通过串口观察启动日志，确认串口配置生效：

```bash
# 串口终端中应能看到 Linux 内核启动日志
# 确认 cmdline 包含 console=ttyAMA0,115200
cat /proc/cmdline
```

**2.6 验证 dm-verity 已禁用**

重新刷机并启动后，验证 `adb remount` 可正常执行：

```bash
adb root
adb remount
```

若输出 `remount succeeded` 则禁用成功。

若仍报错 "Device must be bootloader unlocked"，按以下步骤排查：

1. 检查 `ro.boot.verifiedbootstate` 属性：
   ```bash
   adb shell getprop ro.boot.verifiedbootstate
   # 预期输出：orange
   ```
   若输出为空，说明 `BOARD_KERNEL_CMDLINE` 未包含 `androidboot.verifiedbootstate=orange`，需确认 P1 步骤1已应用。

2. 检查 cmdline 是否包含该参数：
   ```bash
   adb shell cat /proc/cmdline | grep verifiedbootstate
   # 预期输出：androidboot.verifiedbootstate=orange
   ```

3. 确认 BoardConfig.mk 修改已保存且已重新编译刷机。

执行要求：
- BoardConfig.mk 已添加 `androidboot.verifiedbootstate=orange` 到 `BOARD_KERNEL_CMDLINE`
- BoardConfig.mk 已添加 `BOARD_BUILD_DISABLED_VBMETAIMAGE := true`
- config.txt 已添加 `enable_uart=1` 和 `dtoverlay=uart0-pi5`，BoardConfig.mk 已将 `console=ttyAMA10` 改为 `console=ttyAMA0`
- 已重新编译并刷写镜像（完整镜像或单独 boot 分区）
- `adb root` 和 `adb remount` 执行成功
- `adb shell getprop ro.boot.verifiedbootstate` 输出 `orange`
- 串口可正常输出启动日志

### 内核增量编译与更新

树莓派5在AOSP中使用预编译内核镜像（`device/brcm/rpi5-kernel/Image`），源码树不包含内核源码。如需修改内核配置或驱动，需单独获取内核源码编译。

> **版本说明**：raspberry-vanilla 项目预编译内核为 **6.6.116**，源码来自 `raspberry-vanilla/android_kernel_brcm_rpi` 的 `android-15.0` 分支。该仓库基于 AOSP `common-android15-6.6-lts` 基线，叠加了树莓派5的板级补丁，是 Android 15 完整可用的内核源码。

**3.1 获取内核源码**

使用 AOSP 内核构建框架的标准方式获取源码：

```bash
# 创建独立内核构建目录
mkdir -p /home/lechao/workspace/rpi5-kernel-build
cd /home/lechao/workspace/rpi5-kernel-build

# 初始化 AOSP kernel manifest（common-android15-6.6-lts 基线）
repo init -u https://android.googlesource.com/kernel/manifest -b common-android15-6.6-lts

# 添加 raspberry-vanilla 设备配置（替换 kernel/common 为树莓派5源码）
curl -o .repo/local_manifests/manifest_brcm_rpi.xml -L \
  https://raw.githubusercontent.com/raspberry-vanilla/android_kernel_manifest/android-15.0/manifest_brcm_rpi.xml --create-dirs

# 同步源码（约 25GB，网络慢可能需要较长时间）
repo sync -c -j4
```

> **网络问题**：`android.googlesource.com` 国内可能访问缓慢，建议配置代理或使用镜像源。repo sync 过程中如超时中断，重新执行 `repo sync -c -j4` 补齐即可。

同步完成后目录结构：

| 目录/文件 | 说明 |
|-----------|------|
| `common/` | 内核源码（`raspberry-vanilla/android_kernel_brcm_rpi`，6.6.116） |
| `prebuilts/` | 编译工具链（clang、GCC、build-tools 等） |
| `build/kernel/` | Kleaf 构建规则（可选，本文使用 make 方式） |
| `vendor/brcm/` | 树莓派固件文件 |

**3.2 编译内核**

使用 AOSP Clang 工具链编译，无需额外安装交叉编译器：

```bash
cd /home/lechao/workspace/rpi5-kernel-build/common

# 设置 AOSP Clang 工具链到 PATH
export PATH="/home/lechao/workspace/rpi5-kernel-build/prebuilts/clang/host/linux-x86/clang-r522817/bin:$PATH"

# 设置编译环境变量
export ARCH=arm64

# 使用 raspberry-vanilla 官方 android_rpi5_defconfig 配置内核
make O=../out/android_rpi5 CC=clang LD=ld.lld AR=llvm-ar NM=llvm-nm \
  STRIP=llvm-strip OBJCOPY=llvm-objcopy OBJDUMP=llvm-objdump \
  READELF=llvm-readelf HOSTCC=clang HOSTCXX=clang++ HOSTAR=llvm-ar \
  HOSTLD=ld.lld CROSS_COMPILE=aarch64-linux-gnu- \
  CLANG_TRIPLE=aarch64-linux-gnu- android_rpi5_defconfig

# 编译内核镜像 + 设备树 + overlays
make O=../out/android_rpi5 CC=clang LD=ld.lld ... \
  CROSS_COMPILE=aarch64-linux-gnu- CLANG_TRIPLE=aarch64-linux-gnu- \
  Image dtbs -j$(nproc)
```

> **提示**：首次使用 `make ... android_rpi5_defconfig` 后，后续只需执行 `make ... Image dtbs -j$(nproc)` 即可增量编译。
>
> **编译时间参考**：首次编译约15-30分钟（取决于CPU性能），增量修改后约1-3分钟。

编译产物位置：

| 产物 | 路径 |
|------|------|
| 内核镜像 | `out/android_rpi5/arch/arm64/boot/Image` |
| dtb | `out/android_rpi5/arch/arm64/boot/dts/broadcom/bcm2712*.dtb` |
| overlays | `out/android_rpi5/arch/arm64/boot/dts/overlays/*.dtbo` |

> **关键**：`android_rpi5_defconfig` 与预编译内核使用的配置完全一致，已包含 4K 页大小、Android Binder、ASHMEM、IKCONFIG 等所有必要选项，无需额外修改。

**3.3 替换预编译内核**


## 常见问题与排查
- **adb root失败**：确认构建类型为 `eng` 或 `userdebug`，`user` 版本不支持root；检查设备上的 `adbd` 是否正常启动、当前网络ADB连接是否稳定
- **adb remount失败**：先执行 `adb root` 再执行 `adb remount`；若仍报 "Device must be bootloader unlocked"，检查 `adb shell getprop ro.boot.verifiedbootstate` 是否输出 `orange`，若为空则说明 `BoardConfig.mk` 的 `BOARD_KERNEL_CMDLINE` 未包含 `androidboot.verifiedbootstate=orange`，需按本章节第2步配置并重新编译刷机
- **推送后文件权限异常**：推送后检查文件权限与属主，必要时通过 `adb shell chmod` 和 `adb shell chown` 修正
- **修改后设备无法启动**：通过串口查看启动日志定位问题，使用SD卡重新刷入完整镜像回退
- **模块编译报依赖错误**：确认 `source build/envsetup.sh` 和 `lunch` 已执行，检查模块名称是否正确
- **内核编译缺少交叉编译工具**：使用AOSP自带的clang工具链（位于 `prebuilts/clang/host/linux-x86/clang-r522817/bin/`），无需单独安装 GCC 交叉编译器。确保在 `PATH` 中包含了该目录。
- **内核配置项不生效**：确认使用的是 `android_rpi5_defconfig`（不是 `bcm2712_defconfig`）；使用 `make O=out ARCH=arm64 menuconfig` 检查配置是否实际启用；部分配置项有依赖，需先启用前置选项
- **替换内核后设备无法启动**：通过串口查看启动日志；恢复备份内核；或使用 `git checkout -- Image bcm2712-rpi-5-b.dtb overlays/` 恢复预编译内核；最坏情况使用 `/home/lechao/workspace/aosp/rpi5-mkimg.sh` 重新生成完整镜像刷入SD卡
- **内核日志无调试输出**：检查 `CONFIG_USB_STORAGE_DEBUG` 是否生效（`adb shell zcat /proc/config.gz | grep USB_STORAGE_DEBUG`）；提高日志级别（`adb shell 'echo 8 > /proc/sys/kernel/printk'`）
- **自编译内核后设备反复重启卡在 logo**：确认使用的是 raspberry-vanilla 官方 `android_rpi5_defconfig`（不要使用 `bcm2712_defconfig`）；确认 dtb 和 overlays 已同步更新。若仍无法启动，回退到预编译内核验证是否为内核配置问题。
- **自编译内核版本与预编译内核不匹配**：使用 raspberry-vanilla 官方 `android_kernel_brcm_rpi` 的 `android-15.0` 分支（与预编译内核同源，commit `06e9d6ca8fe9`），不存在版本不匹配问题。可通过 `strings Image | grep "Linux version"` 查看内核版本。
- **只替换Image未同步更新dtb和overlays**：自编译内核后必须同步更新 `bcm2712-rpi-5-b.dtb`、`bcm2712d0-rpi-5-b.dtb` 和 `overlays/*.dtbo`，否则因内核与设备树不匹配导致启动失败。
