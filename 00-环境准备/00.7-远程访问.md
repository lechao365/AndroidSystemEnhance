# 远程访问

## 章节目标
在跨网络（不限同一 WiFi）场景下，通过受信任的 HTTPS 加密链路，从移动端浏览器安全访问运行在 WSL2 中的 opencode WebUI，并采用纵深防御策略将攻击面收窄到最小。

## 适用范围
- 已完成 `00.1 WSL2环境搭建`，且 WSL2 处于 **mirrored 网络模式**（localhost 与 Windows 宿主互通）
- 已按 `00.6 开发调试环境` 安装 opencode（`npm install -g opencode-ai`）
- 需要在任意网络（4G/5G/外网）下用手机或平板访问宿主 opencode 会话的开发者
- 不适用于需要公网任意用户访问的场景（本方案仅授权设备可达）

## 前置条件
- Windows 11 + WSL2（mirrored 网络模式，systemd 已启用）
- 一个可注册 Tailscale 账号的邮箱（免费版支持 100 台设备）
- 手机（Android/iOS）可安装 Tailscale 客户端
- opencode 全局已安装，`opencode web --help` 可正常执行

## 环境/硬件准备
| 组件 | 说明 |
|------|------|
| WSL2 | mirrored 模式，eth1 直接持有局域网 IP，与 Windows 共享 localhost |
| Windows 宿主 | DESKTOP-RA5VTNU，安装 Tailscale 客户端（`100.66.65.41`） |
| 移动设备 | Android 手机 `v2454a`（`100.106.173.18`），登录同一 Tailscale 账号 |
| Tailscale Tailnet | `tailcaab0b.ts.net`，账号 `lechao365@gmail.com`（owner） |

## 方案选型对比

远程访问 opencode WebUI 有多种实现，按安全性、易用性、网络适应性对比如下：

| 方案 | 适用网络 | 手机装 App | 加密 | 配置复杂度 | WSL IP 稳定性 |
|------|----------|------------|------|------------|---------------|
| **Tailscale + Serve（本方案）** | 跨网络 | 是 | WireGuard + 受信任 HTTPS | 中 | 走 tailnet 主机名，稳定 |
| Cloudflare Tunnel | 公网任意位置 | 否 | 自动 HTTPS | 中（需域名） | 稳定 |
| 局域网端口转发 | 仅同一 WiFi | 否 | HTTP 明文 | 低 | 受 WSL IP 变化影响 |
| Caddy 反代 + 自签 HTTPS | 仅同一 WiFi | 否 | HTTPS（手机需信任证书） | 中高 | 受 WSL IP 变化影响 |

**选用 Tailscale + Serve 的理由**：同时满足跨网络、端到端加密、受信任证书（浏览器无警告）、零公网 IP、零端口转发，且与 WSL2 mirrored 模式天然契合。

## 整体架构

```
手机浏览器
   │ HTTPS (Let's Encrypt 受信任证书)
   ▼
desktop-ra5vtnu.tailcaab0b.ts.net:443   ← Tailscale Serve 终止 TLS
   │ WireGuard 加密（tailnet 内）
   ▼
Windows Tailscale 客户端
   │ mirrored 模式 localhost 互通
   ▼
WSL2 127.0.0.1:4096  (opencode web, 仅监听 loopback)
   │ Basic Auth 校验
   ▼
opencode 会话
```

攻击面收窄到：只有「你的手机 + tailnet 凭证 + opencode 密码」三者齐全才能进入。公网完全不可见，tailnet 内其他设备也被 ACL 挡在 443 之外。

## 纵深防御（7 层）

| 层 | 防护目标 | 措施 | 状态 |
|----|----------|------|------|
| L0 账号 | 防 Tailscale 账号被盗 | OAuth 登录 + 开启 2FA + Device Approval（新设备需手动批准） | 必选 |
| L1 接入锁 | 防账号被盗后私加设备 | Tailnet Lock（本地密钥签名新节点） | 可选，本方案未启用 |
| L2 ACL | 防 tailnet 内横向移动 | 最小权限 ACL：仅 `tag:phone` → `tag:win-host:443`，其余全 deny | 必选 |
| L3 暴露范围 | 防公网扫描/爆破 | 只用 `tailscale serve`（仅 tailnet 可达），绝不用 `tailscale funnel` | 必选 |
| L4 传输加密 | 防窃听/中间人 | WireGuard + Tailscale 自动签发的受信任 HTTPS 证书 | 必选（内置） |
| L5 应用认证 | 防未授权访问 WebUI | opencode `OPENCODE_SERVER_PASSWORD`（28 位随机），存 600 权限文件，不进 history | 必选 |
| L6 服务托管 | 防崩溃后裸奔 | systemd user unit 托管，崩溃自重启，linger 常驻 | 必选 |

> **Tailnet Lock 权衡**：启用后即使账号被盗也无法加新设备，但每次换设备都要用已签名终端重新签名。换设备频率低、账号被盗风险持续，建议长期启用。

## 操作步骤

### 0. Tailscale 账号加固

1. 访问 [login.tailscale.com](https://login.tailscale.com)，用 GitHub/Google OAuth 注册或登录。
2. **开启 2FA**：Settings → Personal Settings → Account → Multi-factor authentication。
3. **开启 Device Approval**：Settings → Device Management → 勾选 *Require device approval*（新设备加入需手动点 Approve）。
4. 确认 **HTTPS certificates** 已启用（默认启用，免费签发 Let's Encrypt 证书）。

### 1. WSL2 侧：生成强密码并写入环境文件

生成 28 位 URL 安全密码，写入权限 600 的环境文件（不进 shell history、不进 git）：

```bash
PW=$(openssl rand -base64 32 | tr -d '/+=' | cut -c1-28)
mkdir -p ~/.config/opencode
cat > ~/.config/opencode/server.env <<EOF
OPENCODE_SERVER_USERNAME=opencode
OPENCODE_SERVER_PASSWORD=${PW}
EOF
chmod 600 ~/.config/opencode/server.env
echo "请记录密码: ${PW}"
```

> 文件内容参考（实际密码为随机值）：
> ```
> OPENCODE_SERVER_USERNAME=opencode
> OPENCODE_SERVER_PASSWORD=v5mWoNLuvYGLkOAeyElRTH2UAJb6
> ```

### 2. WSL2 侧：编写 systemd user unit

创建 `~/.config/systemd/user/opencode-web.service`：

```ini
[Unit]
Description=OpenCode Web (HTTPS via Tailscale Serve)
Documentation=https://opencode.ai/docs/web/
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
EnvironmentFile=%h/.config/opencode/server.env
WorkingDirectory=%h
ExecStart=/home/lechao/.nvm/versions/node/v20.20.1/bin/opencode web --hostname 127.0.0.1 --port 4096
Restart=on-failure
RestartSec=5
# 安全沙箱：不获取新特权、私有临时目录、系统目录只读
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full

[Install]
WantedBy=default.target
```

**关键点**：
- `--hostname 127.0.0.1`：只绑 loopback，局域网扫描也扫不到，仅 Tailscale Serve 能转发。
- `ExecStart` 中的 opencode 路径需替换为本机实际路径（`which opencode` 查询）。
- **不要加 `ProtectHome=read-only`**：会阻止 opencode 写自己的数据库（`~/.local/share/opencode/opencode.db`），破坏功能。

### 3. WSL2 侧：启用服务并开启 linger

```bash
systemctl --user daemon-reload
systemctl --user enable --now opencode-web.service
loginctl enable-linger lechao   # 让用户级服务在未登录时也常驻
```

验证服务状态：

```bash
systemctl --user status opencode-web.service
ss -tlnp | grep 4096            # 应看到 127.0.0.1:4096 LISTEN
```

### 4. Windows 侧：安装并登录 Tailscale

1. 下载安装 Tailscale 客户端：[tailscale.com/download](https://tailscale.com/download)。
2. 登录第 0 步注册的账号。
3. 在管理员 PowerShell 中验证：
   ```powershell
   & 'C:\Program Files\Tailscale\tailscale.exe' status
   ```
   应显示 `desktop-ra5vtnu` 在线，Tailscale IP 为 `100.66.65.41`。

### 5. Windows 侧：配置 Tailscale Serve

以管理员身份打开 PowerShell，执行：

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' serve --bg --https=443 http://localhost:4096
```

- `--bg`：后台模式，不阻塞终端。
- `--https=443`：用 Tailscale 自动签发的受信任证书在 443 端口对外提供 HTTPS。
- 若首次执行弹出浏览器授权页，点允许即可。

验证：

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' serve status
```

应输出：
```
https://desktop-ra5vtnu.tailcaab0b.ts.net (tailnet only)
|-- / proxy http://localhost:4096
```

> **注意**：`(tailnet only)` 表示仅 tailnet 内设备可达，公网不可见。若误用 `tailscale funnel` 会暴露到公网，**本方案明确禁止**。

### 6. 移动端：安装 Tailscale 并加入 tailnet

1. Android 从 Google Play / F-Droid 安装 Tailscale，iOS 从 App Store 安装。
2. 登录**同一账号**。
3. **保活设置（Android，关键）**，否则后台被杀会导致出门连不上：
   - Tailscale App 设置：开启 *Start on boot* + *Stay connected*。
   - 系统设置 → 应用 → Tailscale → 电池 → 选「不限制/无限制」。
   - 最近任务里把 Tailscale 加锁，防止一键清理。
4. 确认 App 顶部显示 **Connected**（绿色）。
5. Windows 侧验证手机在线：
   ```powershell
   & 'C:\Program Files\Tailscale\tailscale.exe' status
   ```
   应看到 `v2454a android` 不再显示 `offline`。

### 7-8. Tailscale 后台：打 tag 与配置 ACL（必须三阶段顺序）

> **关键坑**：Tailscale 规定「必须先在 ACL 里定义 `tagOwners`，自定义 tag 才会出现在设备的 tag 选择列表里」。若直接去 machines 页面打 tag，会看到列表里没有自定义 tag、无法选中。因此必须按 **阶段 A → B → C** 顺序操作，否则可能把设备锁出 tailnet。

#### 阶段 A：先在 ACL 加 `tagOwners`（acls 暂不动）

1. 打开 [https://login.tailscale.com/admin/acls/file](https://login.tailscale.com/admin/acls/file)。
2. 在现有 JSON 最外层加 `tagOwners` 字段，**保留当前 `acls` 不变**（防止把自己锁出去）：

```jsonc
{
  "tagOwners": {
    "tag:phone":    ["lechao365@gmail.com"],
    "tag:win-host": ["lechao365@gmail.com"]
  },
  "acls": [
    // 此处保留当前已有规则，先不改
  ]
}
```

3. 点 **Save** 保存。

#### 阶段 B：回 machines 页面给设备打 tag

1. 打开 [https://login.tailscale.com/admin/machines](https://login.tailscale.com/admin/machines)。
2. 找到 `desktop-ra5vtnu`（Windows）→ 点右侧 **「⋯」→ Edit ACL tags** → 此时列表中应能看到 `tag:win-host` → 选中。
3. 此时会弹窗提示：
   > *Assigning tags will change the ownership of desktop-ra5vtnu from lechao365@gmail.com to the tag(s) you select. Make sure to update your ACLs accordingly.*

   **这是正常安全提示，点 Confirm/确认 继续**。含义：设备所有权从账号转给 tag，但由于 ACL 的 `tagOwners` 已把这个 tag 的管理权授回给 owner 账号，**不会失去控制**。
4. 对 `v2454a`（Android）同样操作，选中 `tag:phone`，确认提示。

#### 阶段 C：两台设备都打完 tag 后，收紧 acls

1. 回到 [https://login.tailscale.com/admin/acls/file](https://login.tailscale.com/admin/acls/file)。
2. 将编辑器内容整体替换为最终最小权限版：

```jsonc
{
  // 节点打 tag 权限：只有 owner 能给设备打标签
  "tagOwners": {
    "tag:phone":    ["lechao365@gmail.com"],
    "tag:win-host": ["lechao365@gmail.com"]
  },

  "ssh": [],  // 禁用 tailnet SSH

  "acls": [
    // 唯一放行规则：仅手机 tag → Windows tag 的 443 端口
    { "action": "accept", "src": ["tag:phone"], "dst": ["tag:win-host:443"] }
    // 其余全部默认拒绝（无规则即 deny）
  ]
}
```

3. 点 **Save**，规则在 1-2 分钟内全网下发。

效果：tailnet 内任何其他设备（未来新加的、被攻陷的）都打不开 443，横向移动归零。

#### 可选增强（按需放开更多端口）

如后续需要更多能力，在 `acls` 数组追加规则（不破坏最小权限原则）：

```jsonc
// 手机 → Windows:3389（远程桌面 RDP，如需远程操作 Windows）
{ "action": "accept", "src": ["tag:phone"], "dst": ["tag:win-host:3389"] },
```

### 9. 移动端：访问 opencode WebUI

手机浏览器打开：
```
https://desktop-ra5vtnu.tailcaab0b.ts.net
```
弹出 Basic Auth 对话框后输入：
- 用户名：`opencode`
- 密码：第 1 步生成的密码（`cat ~/.config/opencode/server.env` 可查看）

## 验证方法

逐层验证链路：

```bash
# 1. WSL 服务运行 + 仅监听 loopback
systemctl --user status opencode-web.service
ss -tlnp | grep 4096          # 应为 127.0.0.1:4096

# 2. WSL 本地认证（无凭证 401，有凭证 200）
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:4096/
curl -s -o /dev/null -w "%{http_code}\n" -u opencode:密码 http://127.0.0.1:4096/

# 3. Windows 经 mirrored 模式直达 WSL 服务
curl.exe -s -o /dev/null -w "%{http_code}\n" -u opencode:密码 http://localhost:4096/

# 4. Tailscale Serve 配置正确
powershell.exe -NoProfile -Command "& 'C:\Program Files\Tailscale\tailscale.exe' serve status"

# 5. tailnet 设备在线
powershell.exe -NoProfile -Command "& 'C:\Program Files\Tailscale\tailscale.exe' status"

# 6. tailnet 路由连通（ping 手机）
powershell.exe -NoProfile -Command "& 'C:\Program Files\Tailscale\tailscale.exe' ping 100.106.173.18"

# 7. HTTPS 端到端（Windows 侧模拟 tailnet 访问）
curl.exe -s -o /dev/null -w "%{http_code}\n" https://desktop-ra5vtnu.tailcaab0b.ts.net/
curl.exe -s -o /dev/null -w "%{http_code}\n" -u opencode:密码 https://desktop-ra5vtnu.tailcaab0b.ts.net/

# 8. ACL 放行规则生效：tag 已正确下发到设备
powershell.exe -NoProfile -Command "& 'C:\Program Files\Tailscale\tailscale.exe' status --json" > /tmp/ts.json
node -e 'const s=JSON.parse(require("fs").readFileSync("/tmp/ts.json","utf8")); console.log("Self tags:", s.Self?.Tags); (s.Peer?[].constructor===Array?s.Peer:Object.values(s.Peer||{})).forEach(p=>console.log(p.HostName,"tags:",p.Tags));'

# 9. ACL deny 生效：Windows -> 手机非 443 端口应失败（验证横向移动已被阻断）
powershell.exe -NoProfile -Command "Test-NetConnection -ComputerName 100.106.173.18 -Port 22 -InformationLevel Quiet"  # 应返回 False

# 10. 最终：手机浏览器访问 https://desktop-ra5vtnu.tailcaab0b.ts.net 能进入 WebUI
```

预期结果：
- 无凭证访问恒为 `401`，有凭证访问为 `200`
- `tailscale ping` 返回 `pong from v2454a ... in <XX>ms`
- 自检 tag 输出：Self/Peer 的 Tags 分别包含 `tag:win-host` / `tag:phone`
- `Test-NetConnection` 对手机 22/80 等端口返回 `False`（ACL deny 生效）
- 手机浏览器 HTTPS 无证书警告，可正常登录并使用 opencode 会话

## 常见问题与排查

- **手机浏览器无法访问 `*.ts.net` 域名**：通常是 MagicDNS 解析失败。
  - 先用 IP 直连验证：`https://100.66.65.41`。若 IP 能访问、域名不能，确认 Tailscale App 内 MagicDNS 开关开启，且 Android「Private DNS」设为关闭或自动（不能填第三方 DNS 如 AdGuard，否则劫持 `.ts.net` 解析）。
  - 若 IP 也无法访问：确认 Tailscale App 顶部显示 Connected，断开后重连；确认未开启会拦截 tailnet 的 VPN 或防火墙。
- **手机显示 `offline`**：Android 后台省电杀掉 Tailscale。按第 6 步设置电池不限制 + 后台加锁。
- **WSL 服务启动失败**：`journalctl --user -u opencode-web.service -e` 查日志。常见为 `ExecStart` 路径错误（用 `which opencode` 确认）或 `EnvironmentFile` 路径错误。
- **Tailscale Serve 配置命令挂起**：首次配置可能弹出浏览器授权页。直接在 Windows 管理员 PowerShell 执行（不要从 WSL 调 `powershell.exe`，会看不到弹窗导致超时）。
- **443 端口被占用**：`Get-NetTCPConnection -LocalPort 443` 查占用进程。Tailscale Serve 与 IIS/Skype 等会冲突，可改用 `--https=8443`（但手机访问需带端口号）。
- **改了 opencode 配置后 WebUI 不刷新**：`systemctl --user restart opencode-web.service` 重启服务。
- **WSL 重启后服务没起来**：确认 `loginctl enable-linger lechao` 已执行（`loginctl show-user lechao | grep Linger` 应为 `Linger=yes`）。
- **machines 页面打 tag 时列表里没有自定义 tag**：必须先在 ACL 里定义 `tagOwners`（阶段 A）并 Save，自定义 tag 才会出现在设备的 tag 选择列表。顺序错会导致无法选中。
- **打 tag 弹出 "change the ownership ... to the tag(s)" 提示**：这是正常安全提示（设备所有权从账号转给 tag）。只要 ACL 的 `tagOwners` 已把该 tag 的管理权授回给 owner 账号，就不会失去控制，点 Confirm 继续。**切忌在未配 `tagOwners` 的情况下硬确认**，否则可能把设备锁出 tailnet 无人能管理。
- **ACL 保存后未生效**：规则下发需 1-2 分钟。用 `tailscale status --json` 检查设备 Tags 字段是否已更新；用 `Test-NetConnection` 验证 deny 端口是否被拒。
- **手机能连上但 WebUI 提示证书错误**：确认用的是 `https://*.tailcaab0b.ts.net`（Tailscale 自动签发的受信任证书），而非自签证书。

## 运维命令速查

```bash
# 启动/停止/重启
systemctl --user start opencode-web.service
systemctl --user stop opencode-web.service
systemctl --user restart opencode-web.service

# 查看状态与日志
systemctl --user status opencode-web.service
journalctl --user -u opencode-web.service -f       # 实时跟踪日志

# 修改密码
vim ~/.config/opencode/server.env                  # 改 OPENCODE_SERVER_PASSWORD
systemctl --user restart opencode-web.service

# 撤销/重配 Tailscale Serve（Windows PowerShell 管理员）
& 'C:\Program Files\Tailscale\tailscale.exe' serve reset
& 'C:\Program Files\Tailscale\tailscale.exe' serve --bg --https=443 http://localhost:4096

# 完全回滚（卸载）
systemctl --user disable --now opencode-web.service
rm ~/.config/systemd/user/opencode-web.service ~/.config/opencode/server.env
& 'C:\Program Files\Tailscale\tailscale.exe' serve reset
```

## 安全提醒

- `~/.config/opencode/opencode.json` 中若硬编码了明文 API key（如 airproxy/deepseek/visioncoder），opencode WebUI 的 `/config` 接口可能将其泄露给前端。建议将 key 迁到环境变量或 `~/.local/share/opencode/auth.json`（opencode 支持敏感凭据单独存储），**不要**让 WebUI 暴露的同时还把 key 写在配置文件里。
- 本方案未启用 Tailnet Lock，依赖 2FA + Device Approval 兜底账号被盗风险。长期建议启用。
- 密码务必存入密码管理器，`server.env` 文件不要提交到 git（建议在仓库根 `.gitignore` 或本目录 `.gitignore` 排除）。

- 若后续需要暴露更多服务（如 ADB over network、构建监控面板），可复用同一 Tailscale 基础设施，只需追加 ACL 规则。
