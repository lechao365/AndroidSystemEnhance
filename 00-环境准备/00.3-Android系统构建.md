# Android系统构建

## 章节目标
完成首次AOSP完整编译（面向树莓派5），建立对Android平台构建入口的最小认知，知道构建产物在哪里以及后续刷机要用什么。

## 适用范围
- 首次进行AOSP全量构建的学习者
- 以树莓派5为目标的构建场景（基于 raspberry-vanilla 项目）
- 使用 Android 15（android-15.0.0_r32），稳定可靠
- 不涉及Soong/Blueprint/Ninja原理实现，不展开复杂依赖传播路径，不展开构建图生成机制

## 前置条件
- 已完成 `00.1 WSL2环境搭建`，宿主开发环境可用
- 已完成 `00.2 树莓派5硬件认知`，了解目标平台硬件边界
- 至少200GB可用磁盘空间（建议300GB+）
- 内存建议16GB起步，交换分区建议16GB+
- 稳定网络环境（源码下载约100GB+）
- 能访问 GitHub（`raw.githubusercontent.com`）下载树莓派设备配置，如无法访问需配置代理

## 环境/硬件准备
- 编译主机：WSL2 Ubuntu 24.04 或 Linux 工作站
- JDK 17（AOSP主线要求）
- 基础依赖：git、python3、repo、make、gcc等
- 源码目录已规划，例如 `~/workspace/aosp`

## 操作步骤

### 1. 准备源码与工作目录

> **重要**：官方 AOSP 源码不包含树莓派5的设备配置，无法直接编译出树莓派5可用的镜像。需要使用 [raspberry-vanilla](https://github.com/raspberry-vanilla/android_local_manifest) 项目提供的设备配置。

创建工作目录并初始化 repo：

```bash
mkdir -p ~/workspace/aosp
cd ~/workspace/aosp
```

初始化仓库（国内镜像源优先）：

```bash
# 中科大镜像源（推荐，使用 https 协议，git:// 协议可能被限制）
repo init -u https://mirrors.ustc.edu.cn/aosp/platform/manifest -b android-15.0.0_r32 --depth=1

# 或清华镜像源
repo init -u https://mirrors.tuna.tsinghua.edu.cn/git/AOSP/platform/manifest -b android-15.0.0_r32 --depth=1
```

官方源（需代理，国内一般无法直接访问）：

```bash
repo init -u https://android.googlesource.com/platform/manifest -b android-15.0.0_r32 --depth=1
```

> **注意**：`--depth=1` 浅克隆可大幅减少下载量，但后续无法切换分支。镜像源可能限流（HTTP 429），如遇限流错误，降低并发数（`-j4` 或 `-j2`）或等待几分钟后重试。

添加树莓派5设备配置（此步骤需访问 GitHub，如无法访问需配置代理）：

```bash
# 添加树莓派设备 manifest
curl -o .repo/local_manifests/manifest_brcm_rpi.xml -L \
  https://raw.githubusercontent.com/raspberry-vanilla/android_local_manifest/android-15.0/manifest_brcm_rpi.xml --create-dirs

# 可选：移除不需要的项目以减少下载量（移除的都是无关项目，不影响编译）
curl -o .repo/local_manifests/remove_projects.xml -L \
  https://raw.githubusercontent.com/raspberry-vanilla/android_local_manifest/android-15.0/remove_projects.xml
```

同步源码：

```bash
repo sync -j4 -c --no-tags --prune
```

> **参数说明**：
> - `-j4`：4线程并行下载
> - `-c` / `--current-branch`：只同步当前分支，减少下载量
> - `--no-tags`：不下载 git tag，减少数据量
> - `--prune`：删除已不存在的远程分支，保持仓库整洁
>
> 如遇镜像源限流（HTTP 429），降低并发数（`-j2`）或等待几分钟后重试。

执行要求：
- `repo init` 完成无报错
- `curl` 下载设备配置无报错
- `repo sync` 完成后源码目录下出现 `build/`、`frameworks/`、`system/`、`device/brcm/rpi5/` 等目录

### 2. 安装或确认编译依赖
确认编译所需的系统包已安装：

```bash
sudo apt update
sudo apt install -y openjdk-17-jdk git gnupg flex bison gperf build-essential \
  zip curl zlib1g-dev gcc-multilib g++-multilib libc6-dev-i386 \
  libncurses-dev libx11-dev lib32z1-dev \
  libgl1-mesa-dev libxml2-utils xsltproc unzip
```

> **注意**：Ubuntu 24.04 中 `git-core` 已被 `git` 替代，`lib32ncurses5-dev` 和 `libncurses5` 已合并为 `libncurses-dev`，`lib32z-dev` 已被 `lib32z1-dev` 替代，`x11proto-core-dev` 已合并到 `libx11-dev`。

安装树莓派镜像打包所需的额外依赖：

```bash
sudo apt install -y dosfstools e2fsprogs fdisk kpartx mtools rsync
```

确认JDK版本：

```bash
java -version
```

执行要求：
- JDK版本为17
- 上述依赖安装无报错

### 3. 安装并启用 ccache（编译缓存）

ccache 缓存编译中间产物，大幅加速首次和后续增量编译，**必须在首次编译前启用**：

```bash
# 安装 ccache
sudo apt install -y ccache

# 启用 ccache
export USE_CCACHE=1
export CCACHE_EXEC=$(which ccache)

# 设置缓存目录（必须放在 AOSP out/ 目录下，原因见下方说明）
export CCACHE_DIR=~/workspace/aosp/out/ccache
mkdir -p $CCACHE_DIR

# 设置缓存大小（建议 50GB）
ccache -M 50G
```

> **重要：CCACHE_DIR 必须放在 AOSP 的 `out/` 目录下，不可变更！**
>
> AOSP 的 Soong 构建系统会在 nsjail 沙箱中运行 Ninja 编译任务。该沙箱默认将整个根文件系统 `/` 以只读方式挂载，仅将 `out/` 目录挂载为可写。
>
> 如果 `CCACHE_DIR` 指向 `out/` 以外的路径（如 `~/.ccache`、`~/.cache/ccache` 等），ccache 在沙箱内尝试写缓存时会触发 `Read-only file system` 错误，导致编译失败：
> ```
> ccache: error: Read-only file system
> Write to a read-only file system detected.
> ```
>
> **解决方案**：将 `CCACHE_DIR` 设为 `out/ccache` 是唯一稳妥的方案，命中 AOSP 沙箱的可写区域设计。

建议将 ccache 配置写入 `~/.bashrc`，避免每次手动设置：

```bash
echo 'export USE_CCACHE=1' >> ~/.bashrc
echo 'export CCACHE_EXEC=$(which ccache)' >> ~/.bashrc
echo 'export CCACHE_DIR=~/workspace/aosp/out/ccache' >> ~/.bashrc
```

常用 ccache 命令：

```bash
# 查看缓存状态和命中率
ccache -s

# 清空缓存（如遇缓存异常）
ccache -C
```

执行要求：
- `ccache` 已安装
- `USE_CCACHE=1` 已设置
- `CCACHE_DIR` 已设置为 `out/ccache`（**不可变更，否则会报 Read-only file system 错误**）
- 缓存大小已分配（建议 50GB）

**3.1 优化编译并行数**

`-j` 参数控制并行编译任务数，合理设置可避免内存不足导致 OOM：

```bash
# 经验公式：并行数 ≈ CPU核心数，且不超过内存GB数的1.5倍
# 示例：16GB内存 + 8核 → -j12

# 查看CPU核心数和内存
nproc
free -h

# 根据配置选择合适的并行数
make bootimage systemimage vendorimage -j8    # 8核/16GB内存推荐
make bootimage systemimage vendorimage -j12   # 12核/32GB内存推荐
make bootimage systemimage vendorimage -j$(nproc)  # 默认使用所有核心
```

**3.2 增加交换空间**

编译过程内存占用大，增加 swap 可防止 OOM：

```bash
# 查看当前 swap
swapon --show

# 创建 32GB swap 文件
sudo fallocate -l 32G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 永久生效
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

或启用 zram（压缩内存当 swap，性能更好）：

```bash
# 安装 zram-tools
sudo apt install -y zram-tools

# 配置 zram（编辑 /etc/default/zramswap）
sudo sed -i 's/ALGO=lz4/ALGO=lz4/' /etc/default/zramswap
sudo sed -i 's/SIZE=256M/SIZE=16G/' /etc/default/zramswap

# 启用 zram
sudo systemctl enable zramswap
sudo systemctl start zramswap
```

**3.3 将 out 目录挂载为 RAM disk（可选，大内存机器）**

如果内存 ≥ 64GB，可将 `out/` 目录放在内存中，大幅提升 I/O 性能：

```bash
# 创建 RAM disk 挂载点
sudo mkdir -p /mnt/aosp_out

# 挂载 tmpfs（大小根据内存调整，建议 80GB+）
sudo mount -t tmpfs -o size=80G tmpfs /mnt/aosp_out

# 在源码目录创建软链接
cd ~/workspace/aosp
ln -s /mnt/aosp_out out

# 开机自动挂载（添加到 /etc/fstab）
echo 'tmpfs /mnt/aosp_out tmpfs defaults,size=80G 0 0' | sudo tee -a /etc/fstab
```

> **注意**：RAM disk 方案在重启后编译产物会丢失，适合单次完整构建。如需保留产物，构建完成后复制到磁盘：
> ```bash
> cp -r /mnt/aosp_out ~/aosp_out_backup
> ```

执行要求：
- 已根据机器配置选择合适的 `-j` 并行数
- swap 或 zram 已配置（至少 16GB）
- 如使用 RAM disk，已正确创建软链接

### 4. 初始化构建环境
在源码根目录执行：

```bash
source build/envsetup.sh
```

该命令会注册构建所需的shell函数和环境变量。每次打开新终端都需要重新执行。

执行要求：
- 命令执行后终端无报错
- 可使用 `help` 命令查看已注册的构建函数

### 5. 选择目标产品并发起构建
选择树莓派5编译目标：

```bash
lunch aosp_rpi5-bp1a-userdebug
```

可选目标说明：

| lunch 目标 | 说明 |
|---|---|
| `aosp_rpi5-bp1a-userdebug` | 平板 UI（推荐） |
| `aosp_rpi5_tv-bp1a-userdebug` | Android TV |
| `aosp_rpi5_car-bp1a-userdebug` | Android Automotive |

发起构建：

```bash
make bootimage systemimage vendorimage -j$(nproc)
```

首次全量编译耗时较长（1~4小时，取决于机器配置），`-j` 参数控制并行任务数。

执行要求：
- `lunch` 选择了正确的目标产品（`aosp_rpi5-bp1a-userdebug`）
- `make` 命令开始执行并持续输出编译进度

### 6. 打包可刷写镜像
编译完成后，使用树莓派专用脚本打包为可直接写入SD卡的镜像：

```bash
./rpi5-mkimg.sh
```

打包后的镜像文件位于：

```bash
ls out/target/product/rpi5/
```

关键产物说明：

| 产物 | 用途 |
|------|------|
| `RaspberryVanillaAOSP15-*-rpi5.img` | 树莓派5完整刷机镜像（由 `rpi5-mkimg.sh` 生成） |
| `boot.img` | 启动分区镜像（含kernel与ramdisk） |
| `system.img` | 系统分区镜像 |
| `vendor.img` | 厂商分区镜像 |

执行要求：
- `rpi5-mkimg.sh` 执行无报错
- 能在 `out/target/product/rpi5/` 下找到镜像文件
- 知道后续刷机使用 `RaspberryVanillaAOSP15-*-rpi5.img` 写入SD卡

### 7. 记录构建日志与首次失败入口
构建过程中建议保存日志：

```bash
make bootimage systemimage vendorimage -j$(nproc) 2>&1 | tee build_log.txt
```

如果构建失败，先查看日志末尾的错误信息：

```bash
tail -100 build_log.txt
```

常见失败入口：
- 缺少依赖包 → 日志中出现 `command not found` 或 `No such file or directory`
- 磁盘不足 → 日志中出现 `No space left on device`
- 内存不足 → 日志中出现 `OOM` 或进程被 `SIGKILL`

执行要求：
- 构建日志已保存到文件
- 如遇失败，能从日志中定位到错误类型

## 验证方法
- 构建命令 `make bootimage systemimage vendorimage -j$(nproc)` 执行完成且无致命报错（`#### build completed successfully ####`）
- `rpi5-mkimg.sh` 执行成功，生成可刷写镜像
- `out/target/product/rpi5/` 下出现镜像文件
- 构建日志已保存，可供回溯

## 常见问题与排查
- **磁盘不足**：执行 `df -h` 检查剩余空间，AOSP全量构建需要200GB+，清理无用构建产物（`m clean`）或扩展磁盘
- **内存/交换不足**：编译过程中进程被杀，执行 `free -h` 和 `swapon --show` 检查，增加交换分区或减少 `-j` 并行数
- **缺少依赖或版本不匹配**：日志中出现 `command not found` 或版本错误，对照步骤2重新安装依赖，确认JDK版本为17
- **GitHub 无法访问**：`curl` 下载设备配置失败，需配置代理。树莓派设备配置文件托管在 GitHub，国内可能无法直接访问
- **源码同步不完整**：`repo sync` 中断后部分仓库缺失，重新执行 `repo sync -j4` 补齐
- **TLS 连接错误（GnuTLS recv error）**：网络不稳定导致，使用单线程重试：`repo sync -j1 --fail-fast`，逐个仓库同步可提高成功率
- **镜像源限流（HTTP 429）**：降低并发数（`-j4` 或 `-j2`）或等待几分钟后重试
- **ccache 报 Read-only file system**：`CCACHE_DIR` 不在 AOSP 沙箱可写区域内。Soong 构建沙箱将 `/` 只读挂载，仅 `out/` 可写。**必须将 `CCACHE_DIR` 设为 `~/workspace/aosp/out/ccache`，不可使用其他路径**（参见步骤3说明）
- **Cannot extract kernel configs**：VINTF 检查阶段 `extract_kernel.py` 无法从内核提取配置。使用预编译内核时此问题不存在；如自编译内核，确保使用了 `android_rpi5_defconfig`（已默认启用 `CONFIG_IKCONFIG=y`），详见 `00.5 内核增量编译` 章节。
