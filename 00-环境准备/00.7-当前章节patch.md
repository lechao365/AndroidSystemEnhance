## Patch详情

### P1：禁用dm-verity

**解决问题**：Android默认启用dm-verity（验证启动），会校验system/vendor等分区完整性。启用时，`adb remount`会报错"Device must be bootloader unlocked"，无法推送修改后的文件到系统分区。树莓派5没有传统bootloader锁定机制，需要从构建层面禁用dm-verity。

**修改目录**：`device/brcm/rpi5/BoardConfig.mk`

**修改内容**：

**步骤1**：在 `BOARD_KERNEL_CMDLINE` 中添加 `androidboot.verifiedbootstate=orange`：

```makefile
# 修改前
BOARD_KERNEL_CMDLINE := console=ttyAMA0,115200 no_console_suspend root=/dev/ram0 rootwait androidboot.hardware=rpi5

# 修改后
BOARD_KERNEL_CMDLINE := console=ttyAMA0,115200 no_console_suspend root=/dev/ram0 rootwait androidboot.hardware=rpi5 androidboot.verifiedbootstate=orange
```

> **原理说明**：
> - `adb remount` 会检查 `ro.boot.verifiedbootstate` 属性是否为 `"orange"`（表示 bootloader 已解锁）
> - 该属性由 bootloader 通过 kernel cmdline 传递（`androidboot.verifiedbootstate=orange`）
> - 树莓派5的 GPU bootloader 不会设置此参数，需要在构建时通过 cmdline 显式指定
> - 源码位置：`system/core/fs_mgr/fs_mgr_remount.cpp:638-641`

**步骤2**：在文件末尾添加以下配置：

```makefile
# 禁用 dm-verity（开发调试需要）
BOARD_BUILD_DISABLED_VBMETAIMAGE := true
```

**验证方法**：重新编译刷机后，执行`adb root && adb remount`，输出`remount succeeded`即成功。

**影响范围**：
- 构建产物不再包含vbmeta验证镜像
- system/vendor分区可被`adb remount`重新挂载为可写
- 不影响设备正常启动和运行

**回滚方法**：删除添加的配置行，重新编译刷机。

### P2：启用串口控制台

**解决问题**：树莓派5默认未启用40-pin排针上的UART串口输出，且系统console指向SoC内置串口（ttyAMA10），导致40-pin GPIO14/15上的USB转串口模块看不到启动日志。需要同时启用RP1 UART0硬件并将console切换到ttyAMA0。

**修改目录**：
1. `device/brcm/rpi5/boot/config.txt`
2. `device/brcm/rpi5/BoardConfig.mk`

**修改内容1**：`device/brcm/rpi5/boot/config.txt`，在 `# UART` 注释下添加：

```txt
# UART
enable_uart=1
dtoverlay=uart0-pi5
```

**修改内容2**：`device/brcm/rpi5/BoardConfig.mk`，将 `console=ttyAMA10` 改为 `console=ttyAMA0`：

```make
# 修改前
BOARD_KERNEL_CMDLINE := console=ttyAMA10,115200 no_console_suspend root=/dev/ram0 rootwait androidboot.hardware=rpi5

# 修改后
BOARD_KERNEL_CMDLINE := console=ttyAMA0,115200 no_console_suspend root=/dev/ram0 rootwait androidboot.hardware=rpi5
```

> **原理说明**：
> - `enable_uart=1`：通知固件启用UART，调整核心频率避免波特率偏移
> - `dtoverlay=uart0-pi5`：加载RP1 UART0设备树覆盖，启用GPIO14/15上的串口
> - `console=ttyAMA0`：告诉内核将启动日志输出到RP1 UART0（即40-pin串口），而非SoC内置串口（ttyAMA10）

> **ttyAMA0 vs ttyAMA10 — 防止配置错误的关键区别**：
>
> 这是树莓派5上**两个完全不同的物理串口**，不可混用：
>
> | | ttyAMA0 | ttyAMA10 |
> |---|---------|----------|
> | 硬件来源 | RP1芯片上的UART0 | BCM2712 SoC内置PL011 |
> | 物理引脚 | **40-pin排针 GPIO14/15（Pin 8/10）** | SoC内部，**未引出到40-pin** |
> | 别名 | `serial0` | `serial10`、`uart10` |
> | 设备树节点 | `/axi/pcie@120000/rp1/serial@30000` | `/soc/serial@7d001000` |
> | 可否用于USB转串口调试 | **可以**（接Pin 6/8/10即可） | **不可以**（物理上接不到） |
>
> **常见错误**：将 `console=ttyAMA10` 配置写入 `BoardConfig.mk`，意图让40-pin串口输出日志。但 ttyAMA10 的物理信号没有连接到40-pin排针，所以USB转串口模块接在Pin 8/10上收不到任何数据。**正确做法是使用 `console=ttyAMA0`**，让内核日志输出到RP1 UART0，这才是40-pin排针上能接收到的串口。
>
> **树莓派4与5的差异**：树莓派4的 `ttyAMA0` 就是40-pin串口，不存在 ttyAMA10。树莓派5因为引入了RP1芯片，串口编号体系发生了变化，新增了 ttyAMA10（SoC内置）和多个RP1 UART。不要照搬树莓派4的串口配置经验。

**验证方法**：重新编译刷机后，串口终端应能看到内核启动日志，执行 `cat /proc/cmdline` 确认包含 `console=ttyAMA0,115200`。

**影响范围**：
- boot分区自动包含串口启用配置和RP1 UART0 overlay
- 内核启动日志输出到40-pin GPIO14/15（接USB转串口模块）
- 不影响其他启动参数

**回滚方法**：删除添加的配置行，将 `ttyAMA0` 改回 `ttyAMA10`，重新编译刷机。

## Patch应用顺序

首次搭建环境时，按以下顺序应用patch：

1. **P1 + P2**：修改`BoardConfig.mk`和`config.txt`，重新编译刷机

> **关于内核**：使用预编译内核则无需任何内核patch。如需自编译内核，使用 raspberry-vanilla 官方 `android_rpi5_defconfig` 即可，所有必要选项（4K页、IKCONFIG等）已默认启用，无需额外patch（详见 `00.5` 内核增量编译章节）。

## 一键应用脚本

创建`/home/lechao/workspace/aosp/apply_patches.sh`：

```bash
#!/bin/bash
set -e

AOSP_ROOT="/home/lechao/workspace/aosp"

echo "=== 应用P1：禁用dm-verity ==="
# 步骤1：添加 androidboot.verifiedbootstate=orange 到 BOARD_KERNEL_CMDLINE
if ! grep -q "androidboot.verifiedbootstate=orange" "$AOSP_ROOT/device/brcm/rpi5/BoardConfig.mk"; then
    sed -i 's/androidboot.hardware=rpi5$/androidboot.hardware=rpi5 androidboot.verifiedbootstate=orange/' \
        "$AOSP_ROOT/device/brcm/rpi5/BoardConfig.mk"
    echo "P1步骤1已应用（添加androidboot.verifiedbootstate=orange）"
else
    echo "P1步骤1已存在，跳过"
fi

# 步骤2：添加 BOARD_BUILD_DISABLED_VBMETAIMAGE
if ! grep -q "BOARD_BUILD_DISABLED_VBMETAIMAGE" "$AOSP_ROOT/device/brcm/rpi5/BoardConfig.mk"; then
    echo -e "\n# 禁用 dm-verity（开发调试需要）\nBOARD_BUILD_DISABLED_VBMETAIMAGE := true" \
        >> "$AOSP_ROOT/device/brcm/rpi5/BoardConfig.mk"
    echo "P1步骤2已应用"
else
    echo "P1步骤2已存在，跳过"
fi

echo "=== 应用P2：启用串口控制台 ==="
# config.txt
if ! grep -q "dtoverlay=uart0-pi5" "$AOSP_ROOT/device/brcm/rpi5/boot/config.txt"; then
    sed -i '/# UART/a enable_uart=1\ndtoverlay=uart0-pi5\n' "$AOSP_ROOT/device/brcm/rpi5/boot/config.txt"
    echo "P2 config.txt已应用"
else
    echo "P2 config.txt已存在，跳过"
fi

# BoardConfig.mk
if grep -q "console=ttyAMA10" "$AOSP_ROOT/device/brcm/rpi5/BoardConfig.mk"; then
    sed -i 's/console=ttyAMA10/console=ttyAMA0/g' "$AOSP_ROOT/device/brcm/rpi5/BoardConfig.mk"
    echo "P2 BoardConfig.mk已应用"
else
    echo "P2 BoardConfig.mk已存在或已修改，跳过"
fi

echo "=== 所有必要patch已应用 ==="
echo "如需自编译内核，使用 raspberry-vanilla 官方 android_rpi5_defconfig 即可，无需额外patch（详见 00.5）"
```

执行：

```bash
chmod +x /home/lechao/workspace/aosp/apply_patches.sh
/home/lechao/workspace/aosp/apply_patches.sh
```

## 常见问题

- **Q：不应用P1/P2能正常启动吗？**
  - A：能启动，但无法进行增量开发（`adb remount`失败）和串口调试。

- **Q：不自编译内核需要应用内核patch吗？**
  - A：不需要。使用预编译内核时，所有必要选项已包含，无需任何内核patch。

- **Q：应用patch后需要重新编译吗？**
  - A：需要。P1/P2需要重新编译boot/system/vendor镜像并刷机。自编译内核时需要按`00.5`章节的步骤编译、替换、重新构建AOSP。

- **Q：patch会影响系统稳定性吗？**
  - A：不会。P1/P2是开发调试的标准配置，不影响系统稳定性。

- **Q：自编译内核后卡logo反复重启怎么办？**
  - A：首先确认使用的是 raspberry-vanilla 官方 `android_rpi5_defconfig`（不要使用 `bcm2712_defconfig`），其次确认 dtb 和 overlays 已同步更新。也可以回退到预编译内核验证是否为内核问题。
