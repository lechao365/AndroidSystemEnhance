# 环境基线与产批锚点（Definition of Ready）

> **规则 ID**：`ENV-BASE-001` / `ENV-BASE-002`
> 加载时机：方案设计 / 产批（`/cross-device-emit`、`/sync-code-to-doc` 方案先行，
> 或任何以目标设备环境为前提的改动规划）前，凡涉及对目标设备环境的假设
> （文件系统类型、内核编译特性、挂载状态、ABI / 事件 ID 版本、设备节点与
> sysfs 属性等），必须先加载本规则。

## 背景

LcIod 收尾期的 B 工作项（f2fs discard 门禁）在设计阶段假设目标设备 `/data`
为 f2fs，据此规划 discard 策略与 f2fs iostat 耗时门禁。上板只读核查
（收据 `data/verify-results/20261012-153604-7ef21f9f8fc9.md`，提交 `abab5a3`）
实测 `/data` 实为 **ext4**（`/dev/block/mmcblk0p3`），`/proc/fs/f2fs/` 为空目录，
f2fs discard / iostat 在 ext4 上不产生对象，整个 B 方案无对象可测而取消。

根因有二：其一，方案设计前未先测量目标环境基线，把"应该是什么"当成"实际是
什么"；其二，方案设计文本仅存于未入库的会话 / 运行期记录，事后无法从 git
重建，进一步放大了返工成本。本规则把这两点固化为可执行判据。

## ENV-BASE-001 方案设计前必测目标环境基线并随批入 git

- **MUST** 在方案设计 / 产批前，对方案成立所依赖的目标设备环境事实逐项实测
  （只读优先：`/proc/mounts`、`/proc/filesystems`、`/sys` 下块设备与 queue
  属性、`getprop`、ABI 版本宏等），确认假设与实测一致后方可据以设计。
- **MUST** 实测证据随批入 git——以 verify 收据（`data/verify-results/*.md`）
  或其他 git 跟踪产物承载，可被下游批次引用与复核。
- **MUST NOT** 以"目标应如此""按惯例应如此"等未经实测的推断作为方案前提；
  确无法实测（设备不可达等）时，须在方案中显式标注为**前提假设**并给出验证
  计划与回退，不得静默当作已成立事实。
- **校验**：方案 / 批次文本出现目标环境断言（文件系统 / 内核特性 / ABI 等）时，
  必须能指向一份 git 跟踪的收据或产物；无证据即视为未实测。

## ENV-BASE-002 产批锚点必须 git 可见文件，禁引未入库文档

- **MUST** 批次方向（`方向:`）与方案文档中用于定位改动的锚点（文件路径、行号、
  结构体 / 宏名）必须指向 **git 跟踪文件**，即在干净克隆（无任何运行期产物）
  下可复现定位。
- **MUST NOT** 以 gitignore 域文件（`harness/log/` 下运行日志与批次临时文件、
  打点文件、会话记录等未入库文档）作为唯一锚点或方案依据；此类内容不可被
  下游 apply 设备与干净克隆复核。
- 需长期引用的设计 / 契约文本应落盘到 git 跟踪路径（如 `docs/`、
  `harness/rules/`），不得仅存于运行期日志。
- **校验**：方向 / 方案中的路径锚点在干净克隆下可解析到跟踪文件；引用
  `harness/log/` 等未入库域即视为锚点不合规（CDP-DOD-002 同口径）。

## 违规后果

- 违反 ENV-BASE-001：方案建立在不存在的环境假设上（如 f2fs 门禁挂在 ext4
  设备），实测即返工取消 → 方案冻结 / 产批前补齐基线实测证据，否则不得产批。
- 违反 ENV-BASE-002：锚点在干净克隆不可复现，下游无从定位 / 复核 → 批次退回
  重产，以 git 跟踪文件替换锚点后重发。
