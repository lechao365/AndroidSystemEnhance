# Known-Issues 准入规则（有序四门 + 辅助规则）

> **规则 ID**：`KIR-001` ~ `KIR-007`
> - **KIR-001（引入判据）**：缺陷**仅存在于本任务新增或改写的代码路径**才算本任务引入。
>   判法：回退本任务改动，看缺陷是否消失——消失即引入，不消失即非引入。
>   上批改动只提高发作概率而缺陷本身早已存在的，不算引入。
> - **KIR-002（阻塞判据）**：本任务验收或编译或单测**因它失败且重跑仍失败**才算阻塞。
>   重跑即过的属抖动或时序竞态，不算阻塞；登记时须把重跑结果写进正文。
> - **KIR-003（关联判据）**：关联度**只查是否在开工冻结清单内**，不做相关性论证。
>   清单由人工在开工时确认，任务期内不得追加。
> - **KIR-004（severity 排期）**：severity 取 P0 / P1 / P2，可判定但不参与准入，只决排期。
>   P0 登记后立即提专项任务建议，不等阈值。
> - **KIR-005（存量告警）**：status 属 open 或 scheduled 的条目达 8 条时产批前告警。
>   只告警不阻断——阻断会连开专项任务的批次一起卡住。
> - **KIR-006（promote 归档语义）**：闭环只标 fixed 或 wontfix 并填 resolved_in；
>   终态条目不在写时老化，也不在 promote 时删除，改由 promote 晋升时归档进基线
>   文档（证据快照）新增「已修复问题归档」段落（逐条记 id/标题/修复提交），
>   evidence.known_issues_closed 清单同步入档供 yaml 复核；registry 不清零，
>   终态记录随基线文档与 registry 双重留存，证据链可追溯。
> - **KIR-007（灾难级破例）**：灾难级破例须人工确认，LLM 只可列缺陷与影响面提请，不得自行升级。
>   本条不设机械判据是有意的——设了会变成绕过 KIR-001~003 三门的通道。

## 核心原则

缺陷归属必须落进二分法：**命中 KIR-001~003 任一 → 当批修；全不命中 → 登记 known-issues**。
不留第三种归属，不留裁量空间——归属判定是机械查找，不是论证。
登记后的生命周期由 KIR-004~007 管理（severity 只排期不参与准入、存量只告警不阻断、
闭环只标终态待 promote 归档、灾难级破例只能人工确认），均不改变准入判定本身。

## 有序判据（先匹配先生效）

按 KIR-001 → KIR-002 → KIR-003 顺序逐个判定，命中即止：

| 门 | 判据 | 判定方法 | 命中处置 |
|----|------|---------|---------|
| KIR-001 引入判据 | 缺陷仅存在于本任务新增或改写的代码路径 | 回退本任务改动，缺陷消失 = 引入；不消失 = 非引入。上批改动只提高发作概率而缺陷本身早已存在的，不算引入 | 当批修复 |
| KIR-002 阻塞判据 | 本任务验收 / 编译 / 单测因它失败 | 重跑仍失败 = 阻塞；重跑即过 = 抖动或时序竞态，不算阻塞（登记时须把重跑结果写进正文） | 当批修复 |
| KIR-003 关联判据 | 是否在开工冻结清单内 | 只查清单，不做相关性论证。清单由人工在开工时确认，任务期内不得追加 | 当批修复 |
| 全不命中 | — | 上述三判据均不成立 | 登记 known-issues（含重跑结果/回退验证等证据） |

## 准入辅助规则

| 规则 | 语义 | 处置 |
|------|------|------|
| KIR-004 severity | P0 / P1 / P2，可判定但不参与准入 | 只决排期；P0 登记后立即提专项任务建议，不等阈值 |
| KIR-005 存量告警 | status 属 open 或 scheduled 的条目达 8 条 | 产批前告警，只告警不阻断 |
| KIR-006 promote 归档 | 闭环标 fixed 或 wontfix 并填 resolved_in，不设写时配额 | 终态条目由 promote 晋升归档进基线文档「已修复问题归档」段落（id/标题/修复提交），evidence.known_issues_closed 同步入档；registry 不清零、文件不删除 |
| KIR-007 灾难级破例 | 破例须人工确认 | LLM 只可列缺陷与影响面提请，不得自行升级；不设机械判据 |

## 准入场景表（以下六类均登记）

| 场景 | 特征 | 归属 |
|------|------|------|
| 历史遗留且清单外且重跑可过 | KIR-002 重跑即过 + 不在开工冻结清单内 | 登记（正文写重跑结果） |
| 只提高发作概率 | 上批改动提高发作概率，缺陷本体早已存在（KIR-001 回退验证不消失） | 登记（正文写回退验证结果） |
| 需跨技术边界 | 修复需刷 boot.img 等超出本任务改动边界 | 登记（正文写所需边界） |
| 仅特定平台显现 | 只在特定硬件/平台复现 | 登记（正文写复现平台） |
| 命名注释残留 | 命名不一致、注释过时等非功能性残留 | 登记（可并入清理专项） |
| 加固建议非缺陷 | 防御性加固建议，当前无实际故障路径 | 登记（不入缺陷流程） |

## 禁止行为

| 禁止行为 | 原因 | 正确做法 |
|---------|------|---------|
| 用 KI 前缀命名规则 ID | KI 是 known-issues 问题编号前缀，规则用同前缀会撞形 | 规则统一用 KIR 前缀（KIR-001~007） |
| 缺陷归属留给 AI 裁量（"相关""可能有关"等论证） | 归属判定须机械可复现，论证空间会把问题洗成登记 | 按 KIR-001~003 有序判据机械判定，命中当批修、全不命中登记 |
| 对 KIR-003 做相关性论证（"虽然不是冻结清单但看起来相关"） | 任务期内清单冻结是人工开工时的承诺，任务期内不得追加 | 只查清单成员关系；不在清单内即全不命中路径，登记处理 |
| 把抖动/时序竞态登记为阻塞 | 重跑即过说明非确定性失败，阻塞语义是"重跑仍失败" | 重跑即过按非阻塞登记，并把重跑结果写进正文 |
| 把上批改动提高发作概率的既有缺陷算作本任务引入 | 缺陷本体早已存在，非本任务代码路径引入 | 回退本任务改动验证缺陷不消失后，按非引入登记 |
| 让 severity 参与准入判定 | KIR-004 只决排期，severity 与"是否当批修"无关 | severity 仅用于排期；P0 提专项任务建议 |
| KIR-005 存量告警升级为阻断 | 阻断会连开专项任务的批次一起卡住 | 只告警不阻断，由人工决定是否暂停产批 |
| 写时配额老化删除终态条目 | 老化只删最旧记录、丢失已闭环清单全貌，且把删除时机耦合到写入路径 | 写时只登记不改删；promote 晋升时归档进基线文档「已修复问题归档」段落（清单同步入档 evidence.known_issues_closed，文件保留不清零） |
| promote 晋升时删除终态条目 | 删除后 registry 无全量闭环记录，历史基线文档曾丢失全部问题信息（BL-20260905-01 补录教训） | promote 只归档不删除：归档段逐条记 id/标题/修复提交，registry 与基线文档双重留存 |
| LLM 自行升级灾难级破例 | 破例绕过准入三门，自行升级等于自开通道 | 只列缺陷与影响面提请，人工确认后才可走破例 |
