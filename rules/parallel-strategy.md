# 并行策略

## 适用场景

以下场景应主动使用子 agent 并行处理，无需额外确认：

| 场景 | 拆分策略 | 示例 |
|------|---------|------|
| 多文件文档更新 | 按文档章节拆分，每个子 agent 负责一个章节 | `01-打点增强/` 和 `02-IO增强/` 各一个 agent |
| 多文件代码修改 | 按模块/目录拆分，每个子 agent 负责一个模块 | `kernel/` 和 `aosp/` 各一个 agent |
| 代码+文档混合任务 | 代码和文档分派给不同子 agent | 代码改动 + 对应文档更新并行 |

## 拆分原则

1. **独立优先**：子任务间无共享文件、无顺序依赖时，必须并行
2. **文件不重叠**：同一文件只能由一个子 agent 修改，禁止多个 agent 写同一文件
3. **粒度适中**：每个子 agent 负责的文件数不超过 5 个，避免单个 agent 上下文过载

## 禁止并行的场景

- 同一文件的读改写（必须串行）
- 有因果依赖的任务（如先改代码再同步归档）
- 跨目录写入（需确认后才能执行）
