# 文档同步规则（patchs → doc）

## 适用范围

本文件约束 `patchs/rpi5/` 变动到技术文档（`01-打点增强/`、`02-IO增强/` 等）的同步行为，适用于所有 agent 和人工操作。

## 一键生成变动报告

```bash
bash scripts/sync_patchs_to_doc.sh              # 生成变动报告
bash scripts/sync_patchs_to_doc.sh --check-only  # 仅检查，不输出提示信息
```

脚本基于 git HEAD 作为 baseline，对比 `patchs/rpi5/` 的变动，输出结构化报告供 AI 消费。

## 同步流程

```
1. sync_code_to_patchs.sh 归档完成（链路 1）
2. 执行 sync_patchs_to_doc.sh 生成变动报告
3. AI 读取报告，判断影响的技术文档范围
4. AI 输出文档更新方案（具体改哪些文件、改什么内容）
5. 用户确认方案
6. AI 执行文档落盘
```

### 触发时机

完全由用户手动触发，不做自动同步。

## 参与同步的文件类型

| 变动类型 | 说明 | 是否触发文档更新 |
|---------|------|----------------|
| 新增（A） | `patchs/rpi5/` 中新增的文件 | 是 |
| 修改（M） | `patchs/rpi5/` 中已有文件被修改 | 是 |
| 删除（D） | `patchs/rpi5/` 中文件被删除 | 是 |
| 重命名（R） | `patchs/rpi5/` 中文件被重命名 | 是 |

## AI 更新约束

1. **方案先行**：AI 必须先输出文档更新方案（具体改哪些文件、改什么内容），**经用户确认后方可落盘**。禁止未经确认直接修改文档。
2. **增量更新**：AI 以脚本输出的变动报告为输入，仅更新受影响的文档内容，不做全量重写。
3. **自主判断**：AI 根据变动报告自行判断影响的文档范围，不依赖预定义映射表。必要时可读取全量代码以准确理解变更。
4. **保持一致性**：更新后的技术文档应与 `patchs/rpi5/` 中的代码实际状态保持一致。

## 不涉及的文档

`patchs/rpi5/README.md` 文件映射表的更新仍走链路 1（`sync_code_to_patchs.sh` 末尾提示手动更新），不纳入本规则。
