# 1 lechao_lcview_hal 特性定制

## 1.1 概述

`lechao_lcview_hal` 是 lechao vendor 的**结构化日志打点框架**的 vendor 域 HAL 进程，直接 open + epoll 读取内核字符设备 `/dev/vendor_lechao_lcview`，对外暴露 `vendor.lechao.lcview.ILcView` AIDL Pull 接口，供 system 域 Daemon 拉取批量二进制数据。

- **职责**：内核数据的搬运层，不做解析——仅负责从字符设备批量读取二进制数据，缓存后通过 AIDL 接口暴露给 Daemon
- **进程域**：vendor 域常驻进程，由 `lechao_lcview_hal.rc` 启动
- **通信接口**：`vendor.lechao.lcview.ILcView/default`（vndbinder）

Daemon（system 域）的详细设计与实现见 [01.03-Daemon增强-lcview-daemon](./01.03-Daemon增强-lcview-daemon.md)。

## 1.4 AIDL 接口

### 1.4.1 HAL 接口 (vendor 域)

> 完整定义见 [`../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/vendor/lechao/lcview/ILcView.aidl`](./../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/vendor/lechao/lcview/ILcView.aidl)

服务名：`vendor.lechao.lcview.ILcView/default`

```aidl
package vendor.lechao.lcview;

interface ILcView {
    /** 拉取批量数据。有数据立即返回，无数据阻塞最多1s返回空 */
    byte[] getBatch();

    /** 查询溢出计数 */
    int getOverrunCount();
}
```

| 方法 | 返回值 | 说明 |
|------|--------|------|
| `getBatch()` | `byte[]` | Pull 模式：有已缓存 batch 立即返回并清空；无数据返回空 `byte[]`。daemon 轮询调用，间隔由 HAL 内部超时自然控制 |
| `getOverrunCount()` | `int` | 返回内核环形缓冲区累计溢出次数，用于监控是否需要扩容 |

> **设计要点：** Pull 模式对比 Push 回调更健壮——daemon 崩溃重启后直接调 `getBatch()` 无需重新注册回调；daemon 处理慢时自然形成背压，数据在 HAL 内部排队；无 DeathRecipient 生命周期管理。
> **v3.4 优化 (H3):** `getBatch()` 从"立即返回空"改为阻塞等待数据（`condition_variable::wait_for 1s`）。数据到达时由 readerLoop 通过 `mBatchCv.notify_one()` 唤醒，消除 daemon 端每 100ms 无效 Binder 轮询调用。daemon 主循环紧循环调用 `getBatch()` 即可，内部阻塞机制保证 CPU 零开销等待。

### 1.4.2 通信模型

```
daemon (system)                   HAL (vendor)
     │                                │
     ├── getBatch() ──────────────────→
      │                                │ 阻塞返回 mBatch（v3.4: 最多 1s）
     │←── byte[] ─────────────────────┤
     │                                │
     │  [校验 + 格式化 + 写入磁盘]       │  [epoll继续累积下一批]
     │                                │
     ├── getBatch() ──────────────────→
     │   ...
```

## 1.5 HAL 批量读取策略

> 完整实现见 [`../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/hal/LcView.cpp`](./../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/hal/LcView.cpp)

HAL 启动时创建后台 reader 线程，循环执行：

```
readerLoop (后台线程):
    # 启动时查询 ring 初始统计
    ioctl(LCVIEW_GET_STATS) → log total_records/usage/overrun

    while (running):
        epoll_wait(fd, timeout=1000ms)
          ├── 就绪 → read(fd, hal_buf + offset, remaining)
          │            offset += n
          │            if offset == 0: dataArrivedAt = now()   # 记录首字节时刻
          │            数据不足一条记录时忽略（等待后续数据补齐）
          └── 超时 (nfds==0): 继续检查 flush 条件

        # 每 30 次输出心跳 + 诊断计数器
        if beat % 30 == 0:
            LOG(INFO) "alive beat=X buffered=YB readOk=X readErr=X flush=X"

        # flush 条件：有累积数据 && (满 64KB || epoll 超时 || 首字节滞留 > 500ms)
        if offset > 0 && (offset >= 64KB || nfds==0 || ageExpired):
            入队 mBatchQueue, notify cv, offset = 0

        # 每 30 次查询溢出计数
        if beat % 30 == 0:
            ioctl(LCVIEW_GET_OVERRUN) → 累加 mOverrun

    # 退出时打印最终统计
    LOG(INFO) "readerLoop exiting readOk=X readEmpty=X flush=X beat=X"
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `kHalBufSize` | 64KB | HAL 内部累积缓冲区 |
| `kEpollTimeoutMs` | 1000ms | epoll 超时，保证低频数据最多1秒延迟落盘 |
| `kMaxBufferAge` | 500ms | 首字节到达后最多等待 500ms 即强制投递，解决低频事件长时间滞留 mHalBuf |
| 线程安全 | `std::atomic<bool> mRunning` + `std::atomic<int32_t> mOverrun` | mBatchQueue 由 `std::mutex` 保护 |
| `kMaxQueueDepth` | 4 批次 | v3.4: 双缓冲队列最大深度，超过丢弃最旧批次 |

> **设计要点：** HAL 不做解析——只负责搬运二进制数据。解析和校验由 daemon 完成，保持 HAL 轻量。v3.4 优化: (1) 双缓冲队列（最多 4 批次）避免 daemon 未取走时丢失数据，(2) getBatch() 改为阻塞式等待（condition_variable），消除 daemon 无效轮询，(3) overrun ioctl 查询降频到每 30 次循环一次。v2.4 新增: (1) ageExpired 500ms 强制投递条件，消除低频事件数据滞留问题；(2) readerLoop 加入诊断计数器（readOk/readErr/flushCount），心跳日志可呈现数据流全貌；(3) LOG() 日志体系统一。`readerLoop` 中 `PLOG(ERROR)` 和 `LOG(INFO)` 占位符语法统一为 `LOG(ERROR/INFO) << "..." << strerror(errno)`，移除 `<log/log.h>` ALOG* 宏混用；`main_lcview_hal.cpp` 新增 `SetDefaultTag("lechao_lcview_hal")` 和 `KernelLogger`，日志 tag 固定为 `lechao_lcview_hal` 且双写 logd + dmesg。

## 1.6 异常处理

| 异常 | 处理 |
|------|------|
| 设备节点不存在/无权限 | `ueventd.rpi5.rc` 中声明设备节点权限，sepolicy `file_contexts` 打标签 |
| Binder 服务注册失败 | `service_contexts` 需同时包含 `ILcView` 和 `ILcView/default` 两条规则 |
| Daemon 未及时取走数据 | 双缓冲队列（`kMaxQueueDepth=4`）缓存，超限丢弃最旧批次 |

### 1.7.1 AOSP 集成

源码直接位于 AOSP 树内，使用真实目录（非软链接）：

### 1.7.2 device tree 集成（必须）

> **lcview 的两个 `cc_binary` 必须显式加入 `PRODUCT_PACKAGES`**，否则不会被打包进镜像。

#### 1) `device/<vendor>/<device>/device.mk`

```makefile
# lechao lcview service
PRODUCT_PACKAGES += \
    lechao_lcview \
    lechao_lcview_hal \
    vendor.lechao.lcview-service
```

**原理**：`ALL_DEFAULT_INSTALLED_MODULES` 来源于 `product_target_FILES`（即 `PRODUCT_PACKAGES`），未列入的模块只被 ninja install 到 `out/target/` 但不被打入镜像。

#### 2) `BoardConfig.mk`

```makefile
# SELinux 开发模式（允许自定义策略编译通过）
SELINUX_IGNORE_NEVERALLOWS := true

# 内核 cmdline：修正 ttyAMA10→ttyAMA0，关闭验证启动
BOARD_KERNEL_CMDLINE := console=ttyAMA0,115200 no_console_suspend \
    root=/dev/ram0 rootwait androidboot.hardware=rpi5 \
    androidboot.verifiedbootstate=orange

# 禁用 dm-verity（开发调试需要）
BOARD_BUILD_DISABLED_VBMETAIMAGE := true
```

| 选项 | 说明 |
|------|------|
| `SELINUX_IGNORE_NEVERALLOWS` | 允许自定义 SELinux 策略通过编译（`.te` 文件可能违反 neverallow 规则） |
| `androidboot.verifiedbootstate=orange` | 标记设备为 unlocked，允许未签名模块运行 |
| `BOARD_BUILD_DISABLED_VBMETAIMAGE` | 跳过 vbmeta 签名，无需 `fastboot --disable-verity` |

#### 3) `aosp_rpi5.mk`

```makefile
# Bypass VINTF kernel requirement check for self-compiled kernel
PRODUCT_OTA_ENFORCE_VINTF_KERNEL_REQUIREMENTS := false
```

自编译内核的 KMI 模块列表与 AOSP release 配置不完全匹配，跳过此检查。

#### 4) `boot/config.txt`

```ini
# UART（调试串口）
enable_uart=1
dtoverlay=uart0-pi5
```

`enable_uart=1` 启用 UART 硬件，`dtoverlay=uart0-pi5` 将 UART0 映射到 GPIO 14/15（标准调试串口引脚）。

## 1.8 SELinux 策略

完整定义见：
- [`../patchs/rpi5/aosp/new/device/brcm/rpi5/sepolicy/lechao_lcview_hal.te`](../patchs/rpi5/aosp/new/device/brcm/rpi5/sepolicy/lechao_lcview_hal.te)
- [`../patchs/rpi5/aosp/modified/device/brcm/rpi5/sepolicy/file_contexts`](../patchs/rpi5/aosp/modified/device/brcm/rpi5/sepolicy/file_contexts)
- [`../patchs/rpi5/aosp/modified/device/brcm/rpi5/sepolicy/service_contexts`](../patchs/rpi5/aosp/modified/device/brcm/rpi5/sepolicy/service_contexts)

```te
# HAL 域（vendor）
type lechao_lcview_hal, domain;
type lechao_lcview_hal_exec, exec_type, vendor_file_type, file_type;
type lechao_lcview_hal_device, dev_type, file_type;

init_daemon_domain(lechao_lcview_hal)
vndbinder_use(lechao_lcview_hal)

allow lechao_lcview_hal lechao_lcview_hal_device:chr_file { open read write ioctl };
allow lechao_lcview_hal lechao_lcview_hal_service:service_manager add;
```

`file_contexts`：
```
/vendor/bin/lechao_lcview_hal          u:object_r:lechao_lcview_hal_exec:s0
/dev/vendor_lechao_lcview              u:object_r:lechao_lcview_hal_device:s0
```

`service_contexts`：
```
vendor.lechao.lcview.ILcView           u:object_r:lechao_lcview_hal_service:s0
vendor.lechao.lcview.ILcView/default   u:object_r:lechao_lcview_hal_service:s0
```

> **注意：** 两条规则都需要，`selabel_lookup` 会匹配含 `/default` 后缀的完整服务名。如果仅注册 `vendor.lechao.lcview.ILcView` 不含 `/default`，SELinux 会拒绝服务注册（返回 `-1`）。详细原理见 [11.06-开机优化/.../service_contexts.md]。
