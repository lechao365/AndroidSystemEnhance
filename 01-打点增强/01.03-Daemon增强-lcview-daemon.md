# 1 lechao_lcview Daemon 特性定制

## 1.1 概述

`lechao_lcview` 是 lechao vendor 的**结构化日志打点框架**的 system 域 Daemon 进程，通过 Binder AIDL `getBatch()` 从 HAL（vendor 域）拉取批量二进制数据，经 `SchemaParser` 逐字段校验后由 `FileWriter` 按事件 ID 分文件写入 JSONL 格式到本地磁盘。

- **职责**：数据校验层 + 持久化层——从 HAL 拉取二进制数据，按 Schema 校验字段类型和数量，合法记录按事件 ID 写入独立 JSONL 文件
- **进程域**：system 域常驻进程，由 `lechao_lcview.rc` 启动
- **数据源**：通过 vndbinder 连接 `vendor.lechao.lcview.ILcView/default` HAL 服务

HAL（vendor 域）的详细设计与实现见 [01.02-HAL增强-lcview-hal](./01.02-HAL增强-lcview-hal.md)。

**设计目标：**
- **Pull 模式健壮**：daemon 通过 `getBatch()` 无状态拉取，对比 Push 回调模式无回调生命周期管理、无死亡监听、无背压缓冲
- **Schema 驱动校验**：每个事件 ID 对应固定字段 schema（JSON 配置），daemon 逐字段校验类型和数量，不合法记录拒绝落盘
- **按 ID 分文件**：不同 event_id 写入独立 JSONL 文件，便于云端一对一建表和前端查询
- **自动滚动**：按时间（每天）+ 大小（50MB）双重滚动，总占用超限自动删除最旧文件

## 1.4 Schema 解析与校验

> 完整实现见 [`../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/daemon/SchemaParser.cpp`](./../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/daemon/SchemaParser.cpp)

### 1.4.1 Schema JSON 格式

```json
// /vendor/etc/lcview_events.json
{
  "version": 1,
  "events": [{
    "id": 1,
    "name": "usb_connect",
    "desc": "USB 设备连接事件",
    "fields": [
      {"name": "port",    "type": "int32"},
      {"name": "chipset", "type": "string"},
      {"name": "vid",     "type": "int32"},
      {"name": "pid",     "type": "int32"}
    ]
  }]
}
```

内核和 daemon 共享 `lcview_events.h` 中的事件 ID 宏。JSON 文件定义字段名和类型，云端根据 ID 一对一建表。

### 1.4.2 校验流程

每条二进制记录消费路径：

```
rec = parse(batch[offset], &record_len)      # 解析 4B 长度前缀 + 16B 记录头 + 字段区
                                              ↓
schema = SchemaParser::find(rec.event_id)     # 查 JSON schema
  → id 不存在？ → writeInvalid(rec, "unknown id") → 丢弃
                                              ↓
SchemaParser::validate(rec, len, &errMsg)     # 逐字段校验
  → magic != 0x4C56？       → discard
  → field_count 不匹配？     → discard
  → 某字段 type 不符？       → discard
  → 记录长度不匹配？         → discard
                                              ↓
  校验通过 → writeRecord(schema, rec) → 写入磁盘
```

无效记录统一写入 `invalid_records.log`，保留原因和原始数据大小。

## 1.5 文件写入与滚动

> 完整实现见 [`../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/daemon/FileWriter.cpp`](./../patchs/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/daemon/FileWriter.cpp)

### 1.5.1 JSONL 输出格式

每行一个 JSON 对象，不含字段名，`f` 数组按 schema 顺序排列：

```jsonl
{"ts":1738900000123456789,"id":1,"level":3,"f":[1,"dwc3",0x1234,0x5678]}
{"ts":1738900001123456789,"id":1,"level":3,"f":[2,"xhci",0x12D1,0x107E]}
```

| 字段 | 说明 |
|------|------|
| `ts` | 内核打点时的纳秒时间戳 (`ktime_get_real_ns()`) |
| `id` | 事件 ID（对应 schema） |
| `level` | 日志级别 (0=DEBUG, 1=INFO, 2=WARN, 3=ERROR) |
| `f` | 字段值数组，按 schema 顺序排列 |

### 1.5.2 落盘日志输出到 logd

每条 JSONL 记录在落盘前通过 `ALOGI("lechao_lcview: write ...")` 输出到 logcat（daemon 使用 `<log/log.h>` `ALOGI`），方便开发调试时实时查看落盘数据：

```
adb logcat -s lechao_lcview:V | grep "write"
# 输出示例：
# lechao_lcview: write 1 {"ts":1738900000123456789,"id":1,"level":3,"f":[1,"dwc3",0x1234,0x5678]}
```

前缀 `lechao_lcview: write <event_id>` 后跟完整 JSONL 行，方便 grep 按事件 ID 过滤。

### 1.5.3 目录自动创建

数据目录 `/data/vendor/lechao_lcview/` 由两层保障创建：

1. **init.rc 层**：`lechao_lcview.rc` 中 `mkdir /data/vendor/lechao_lcview 0755 system system`，init 阶段创建父目录并自动 `restorecon` 打 SELinux 标签
2. **C++ 兜底层**：`FileWriter` 构造函数中使用 `mkdirRecursive()` 递归创建 `logs/` 和 `uploaded/` 子目录（`mkdir -p` 等价实现），当父目录不存在时逐级向上创建

> **设计原因**：init 的 `mkdir` 只能创建路径的最后一级目录，POSIX `mkdir()` 同理。旧代码中 `mkdir(logDir.c_str())` 在父目录 `/data/vendor/lechao_lcview/` 不存在时静默失败（返回值被忽略），导致 `/data/vendor/lechao_lcview/logs/` 从未被创建。

### 1.5.4 文件滚动策略

| 维度 | 策略 | 可配参数 |
|------|------|---------|
| 按时间切分 | 每天凌晨自动新建文件 | `rotation_interval_h=24` |
| 按大小切分 | 单文件超 50MB 后新建续写 | `maxFileSizeMb=50` |
| 保留策略 | 总占用超 500MB 删除最旧 | `maxTotalSizeMb=500` |
| 文件命名 | `{id}_{name}_{date}_p{seq}.jsonl` | seq 当天同 ID 多切片递增 |

示例：`1_usb_connect_20260603_p0.jsonl` → 满 50MB → `1_usb_connect_20260603_p1.jsonl`

### 1.5.5 目录结构

```
/data/vendor/lechao_lcview/
├── logs/                              # daemon 写入
│   ├── 1_usb_connect_20260603_p0.jsonl
│   ├── 1_usb_connect_20260603_p1.jsonl
│   ├── 2_gpio_irq_20260603_p0.jsonl
│   └── invalid_records.log           # 校验失败的记录
├── uploaded/                          # uploader 归档（二期）
│   └── 1_usb_connect_20260602_p0.jsonl.gz
└── daemon.pid
```

## 1.6 异常处理

| 异常 | 处理 |
|------|------|
| 数据目录不存在 | init.rc `mkdir` 创建父目录，FileWriter 构造函数 `mkdirRecursive()` 递归创建 `logs/`/`uploaded/` |
| 磁盘满 | 删除最旧 uploaded 文件腾空间，仍不足则丢弃 + 记 error |
| 写入 I/O 错误 | 重试 3 次，失败丢弃当前批次 |
| schema 文件缺失/损坏 | 启动 FATAL 退出；运行时 reload 失败沿用已加载版本 |
| Binder 断连（HAL 崩溃） | `getBatch()` 抛异常，daemon 每 100ms×100 次重试循环调用 `AServiceManager_checkService()`（`waitForService` 在 NDK API 1.3.6 中不存在，需自行实现 retry） |
| daemon 自身崩溃 | init.rc `boot_completed` 触发 + `class main` 保证重启 |

## 1.7 编译与使用

### 1.7.1 AOSP 集成

源码直接位于 AOSP 树内，使用真实目录（非软链接）：

```
/home/lechao/workspace/aosp/vendor/lechao/services/lechao_lcview/
```

所有修改直接在此路径进行，编译后同步到 patchs 目录。

### 1.7.2 device tree 集成（必须）

device tree 集成配置（BoardConfig.mk、aosp_rpi5.mk、config.txt）与 HAL 文档相同，详见 [01.02 §1.7.2](./01.02-HAL增强-lcview-hal.md#172-device-tree-集成必须)。

`PRODUCT_PACKAGES` 中 daemon 和 HAL 都需要声明：

```makefile
# lechao lcview service
PRODUCT_PACKAGES += \
    lechao_lcview \
    lechao_lcview_hal \
    vendor.lechao.lcview-service
```

### 1.7.3 编译

```bash
cd /home/lechao/workspace/aosp
source build/envsetup.sh && lunch aosp_rpi5-bp1a-userdebug
m lechao_lcview           # 编译 daemon
```

### 1.7.4 部署与验证

```bash
# 确认二进制已部署
adb shell ls -l /system/bin/lechao_lcview

# 确认 schema 配置
adb shell cat /vendor/etc/lcview_events.json

# 重启触发 init 启动
adb reboot

# 验证 daemon 进程
adb shell ps -A | grep lechao_lcview

# 验证日志目录
adb shell ls -l /data/vendor/lechao_lcview/logs/

# 查看落盘数据（logcat 实时输出）
adb logcat -s lechao_lcview:V | grep "write"
```

```te
# Daemon 域（system）
type lechao_lcview, domain;
type lechao_lcview_exec, exec_type, file_type;

init_daemon_domain(lechao_lcview)
vndbinder_use(lechao_lcview)

binder_call(lechao_lcview, lechao_lcview_hal)
```

`file_contexts`：
```
/system/bin/lechao_lcview              u:object_r:lechao_lcview_exec:s0
/data/vendor/lechao_lcview(/.*)?       u:object_r:lechao_lcview_data_file:s0
```

`service_contexts`：
```
vendor.lechao.lcview.ILcView           u:object_r:lechao_lcview_hal_service:s0
vendor.lechao.lcview.ILcView/default   u:object_r:lechao_lcview_hal_service:s0
```

> **注意：** 两条规则都需要，`selabel_lookup` 会匹配含 `/default` 后缀的完整服务名。如果仅注册 `vendor.lechao.lcview.ILcView` 不含 `/default`，SELinux 会拒绝服务注册（返回 `-1`）。详细原理见 [11.06-开机优化/.../service_contexts.md]。
