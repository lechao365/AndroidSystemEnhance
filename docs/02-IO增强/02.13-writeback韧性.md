# zram writeback 拔盘韧性守护

> 层级：用户态 (system) / 验收 ｜ 事件 ID：`LCVIEW_EVENT_WRITEBACK_GUARD` = **21**
> 验收 case：`case:writeback-guard`（`lciod_check.sh --mode writeback-guard`）
> 巡检周期：**60s**（边沿触发，断供/恢复各上报一次）
> 安全边界：仅只读 sysfs + USB 热插拔 unbind/rebind（可逆）；**无 sdb 块级写**，daemon **不自动重绑**

## 1. 背景与目标

zram0 通过 `backing_dev` 把 idle 换出页写回 USB 后备盘（部署为 `/dev/block/sdb`）。
U 盘拔出、驱动 unbind 或链路异常时，内核把 `backing_dev` 标记为
`/dev/block/sdb (deleted)`，此后的 writeback 会返回错误。若无人观测，故障只能
在后续 IO 报错时被动暴露。

本批新增 **WritebackGuard**：每 60s 只读巡检后备盘供给，供给中断时上报
`lost`、恢复后上报 `recovered`（事件 id=21），把「断供」从静默故障变成可观测事件。

**明确不做自动重绑**：换盘后把 `backing_dev` 指向新设备会丢弃已 writeback 页；
恢复统一留给开机 `rpi5-zram-setup.sh`（swapoff → reset → 绑定当前 U 盘 →
disksize → mkswap → swapon）。守护只负责可见性，不改变 zram 状态。

## 2. 机制与实现

### 2.1 供给判定（纯函数）

`daemon/writeback_guard.{h,cpp}`：

| 步骤 | 判据 |
|------|------|
| 读 `backing_dev` | `/sys/block/zram0/backing_dev`（失败按「无供给」暴露，不静默当正常） |
| 解析设备名 | 剥尾部 ` (deleted)` → `/dev/block/sdb` 取 `sdb`；空/`none` → 无效 |
| 目标存在性 | `/sys/block/<name>` 是否存在 |
| 健康 | 无 `(deleted)` 标记 **且** 设备名有效 **且** 目标存在 |

事件 JSON（`lechao_lciod_event` tag）：

```json
{"rule":"writeback_guard","state":"lost","lost":1,"target_present":0,"backing_dev":"/dev/block/sdb (deleted)"}
{"rule":"writeback_guard","state":"recovered","lost":0,"target_present":1,"backing_dev":"/dev/block/sdb"}
```

事件 id=21 三镜像登记：

| 位置 | 文件 |
|------|------|
| 内核真相源 | `code/rpi5/kernel/new/vendor/lechao/LcView/lcview_events.h` |
| AOSP 镜像头 | `code/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/include/lcview_events.h` |
| schema | `code/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/config/lcview_events.json` |

该事件为 daemon 合成（无内核发射点），在 `harness/lib/check_lcview_events.py` 的
`DISABLED_EVENTS` 登记豁免（与 `slow_disk`=14 / `zram_swap_pressure`=19 / `trim`=20
同口径）。

### 2.2 运行循环

`service.cpp` 的 `WritebackGuardRunLoop`（`IoServiceImpl::start()` detach 启动）：

- 周期 60s，只读采样；`!primed || lost != last_lost` 时上报（首次采样即上报，
  此后仅状态翻转，防周期刷屏）。
- sysfs 读失败按「无供给」暴露；线程不因单次失败退出（CXX-004：非致命观测项）。
- 不写 `backing_dev`、不调用 zram reset、不触发 writeback。

### 2.3 环境基线（apply 侧实测）

| 项 | 实测 |
|----|------|
| zram 后备盘 | `/dev/block/sdb`（`removable=1` 测试 U 盘） |
| 该盘实际驱动 | **usb-storage（BOT）**，USB 接口 `1-2:1.0` |
| 另一 USB 盘 | `/dev/block/sda`，uas 驱动，接口 `2-1:1.0` |
| 断供后 backing_dev | `/dev/block/sdb (deleted)` |
| rebind 行为 | 未释放 stale bdev 时新盘会枚举为 `sdc`；先 zram reset 释放后 rebind 可复用 `sdb` |

> 方向原文写「echo 设备号到 uas/unbind」，但后备盘 sdb 实际绑定 usb-storage；
> 验收实现按 `/sys/block/sdb` 的 sysfs 路径**动态解析接口与实际驱动**（uas 与
> usb-storage 均支持），避免按错误驱动 unbind 影响无关的 sda。

## 3. 验收

`harness/skills/workspace-verify/cases/lciod_check.py --mode writeback-guard`
（case：`writeback-guard`，`timeout_s=300`）：

1. 读 `backing_dev` 解析后备盘，定位其 USB 接口与实际驱动；
2. `echo <iface> > /sys/bus/usb/drivers/<driver>/unbind` 模拟拔盘；
3. 断言 90s 内收到 `state=lost`；断言 daemon 存活；bounded 10s 写
   `zram0/writeback` 返回（报错不挂死）；
4. zram `swapoff + reset` 释放 stale backing → rebind USB → 选取新出现的
   `removable` sd* → 按开机 setup 等价步骤重绑 zram；
5. 断言 90s 内收到 `state=recovered`。

**实测（2026-10-20，设备 192.168.1.13:5555）**：

| 项 | 实测 |
|----|------|
| 断供事件 | `23:28:54.017` `state=lost`，`backing_dev="/dev/block/sdb (deleted)"`，`target_present=0` |
| 断供后 daemon | 存活（`pidof lechao_lciod` 有值） |
| 断供下 writeback | 10s 内返回错误（未挂死） |
| 恢复事件 | `23:29:54.017` `state=recovered`，`backing_dev=/dev/block/sdb`，`target_present=1` |
| 恢复后状态 | swap 重新启用，backing 指向 sdb |
| 单轮验收耗时 | **84.5s**（每段事件窗 ≤60s + 重绑操作） |

防假绿：logcat 锚点使用设备侧时间字符串（`date +"%m-%d %H:%M:%S.000"`）而非
epoch——toybox `logcat -T <纯数字>` 会被解析为「最近 N 行」，epoch 过滤失效会把
上一轮 `recovered` 当前置证据。无 lost / daemon 崩溃 / writeback 挂死 / 无 recovered
均判红。

## 4. 恢复路径与安全边界

### 恢复路径（开机 setup）

1. 断电/拔盘后重启：`rpi5-zram-setup.sh` 在 `on boot` 阶段执行；
2. 脚本先 `swapoff` + reset（释放 stale bdev，使旧 `sdX` 名可复用）；
3. 枚举当前 `removable=1` 的 USB 块设备并绑为 `backing_dev`；
4. 重建 disksize/mkswap/swapon；daemon 下一次巡检上报 `recovered`。

### 安全边界

| 项 | 说明 |
|----|------|
| 读取 | 仅 `/sys/block/zram0/backing_dev` 与 `/sys/block/<dev>` 存在性 |
| 验收动作 | USB 接口 unbind/rebind（热插拔接口，可逆）；异常路径 `finally` 兜底 rebind |
| zram 重绑 | 仅验收侧模拟开机 setup；写的是内存压缩设备，不写 sdb |
| 数据面 | **无 sdb 块级写**、无 dd；最坏 panic 可重启恢复，非变砖 |
