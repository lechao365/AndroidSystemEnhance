## B 取消：环境假设未早期实测

### 原方案与其隐含假设

B 工作项原计划针对 **f2fs** 的 discard 策略与 f2fs iostat 耗时统计设置门禁 / 验收，
其成立前提是目标设备 `/data` 以 f2fs 挂载。

### 只读核查证据

提交 `abab5a3`（2026-10-12 15:36，无代码改动，仅落收据）与收据
`data/verify-results/20261012-153604-7ef21f9f8fc9.md`（`result: skip`）记录了上板只读核查结论：

| 核查项 | 实测值 | 结论 |
|--------|--------|------|
| `/data` 文件系统 | `/proc/mounts` 显示 `/dev/block/mmcblk0p3` 且 fstype=`ext4`；`stat -f /data` 为 `ext3/4` | **非 f2fs** |
| `/proc/filesystems` | 含 `f2fs`（内核编译支持存在） | 有支持，无挂载 |
| `/proc/fs/f2fs/` | 空目录 | 无 f2fs superblock |
| `mmcblk0/queue/discard_max_bytes` | `134217728`（128 MiB） | 块层具备 discard 能力 |
| `mmcblk0/queue/discard_max_hw_bytes` | `22502440960` | 硬件能力上限 |
| `mmcblk0/queue/discard_granularity` | `4194304`（4 MiB） | — |
| `mmcblk0/queue/discard_zeroes_data` | `0` | — |

### 取消判据与教训

f2fs discard / iostat 仅在 f2fs 挂载时产生对象；`/data` 实测为 ext4 且 `/proc/fs/f2fs/`
为空，**B 方案在当前镜像上无对象可测**，故取消。块层 discard 能力具备，可作为未来
切换 f2fs 的硬件前提。

**教训（环境假设未早期实测）**：B 方案在设计阶段把"目标应为 f2fs"当作既定事实，
未先测量目标设备环境基线；且方案设计文本仅存在于未入库的会话 / 运行期记录，
事后无法从 git 重建。为此沉淀 `ENV-BASE-001`（方案设计前必测目标环境基线随批入 git）
与 `ENV-BASE-002`（产批锚点必须 git 可见文件，禁引未入库文档）。

## 事件 ID 实际分配实况

三侧契约（内核 `code/rpi5/kernel/new/vendor/lechao/LcView/lcview_events.h`、AOSP
`code/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/include/lcview_events.h` 与
`code/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/config/lcview_events.json`）
一致。实际共 **16 个事件 ID**，采用**连续递增分配、删除不回收**：

| id | 宏 | 归属 | 说明 |
|----|----|------|------|
| 1 | `LCVIEW_EVENT_USB_CONNECT` | 预留占位 | 无发射点（由 PROBE 替代） |
| 2 | `LCVIEW_EVENT_GPIO_IRQ` | 预留占位 | 无发射点 |
| 3 | `LCVIEW_EVENT_SENSOR_DATA` | 预留占位 | 无发射点 |
| 4 | —（无宏） | 历史空洞 | 原 `USB_TRANSPORT_START`，合并进 END 后删除，不回收 |
| 5 | `LCVIEW_EVENT_USB_TRANSPORT_END` | lciod 内核 | usbd-stats 发射 |
| 6 | `LCVIEW_EVENT_USB_TRANSPORT_ERROR` | lciod 内核 | usbd-stats 发射 |
| 7 | `LCVIEW_EVENT_USB_RESET` | lciod 内核 | usbd-stats 发射 |
| 8 | `LCVIEW_EVENT_USB_PROBE` | lciod 内核 | usbd.c 发射 |
| 9 | `LCVIEW_EVENT_USB_DISCONNECT` | lciod 内核 | usbd.c 发射 |
| 10 | `LCVIEW_EVENT_USB_STALL` | lciod 内核 | usbd-stats 发射 |
| 11 | `LCVIEW_EVENT_USB_TIMEOUT` | lciod 内核 | usbd-stats 发射 |
| 12 | `LCVIEW_EVENT_USB_DATA_CORRUPT` | lciod 内核 | usbd-stats 发射 |
| 13 | `LCVIEW_EVENT_USB_RATE_DEGRADED` | lciod 内核 | usbd-stats 发射 |
| 14 | `LCVIEW_EVENT_SLOW_DISK` | daemon 合成 | R3，无内核发射点 |
| 15 | `LCVIEW_EVENT_SD_HEALTH` | lciod 内核（A） | `lciod_sd.c` 发射 |
| 16 | `LCVIEW_EVENT_SD_STUCK` | lciod 内核（A） | `lciod_sd.c` 发射 |
| 17 | `LCVIEW_EVENT_USB_LATENCY_TAIL` | daemon 合成（C） | C 批二长尾事件 |

要点：**除 id=4 的历史空洞（删除不回收）外，5~17 连续分配**；1~3 为预留占位；
14~17 为较晚新增（slow_disk / SD_HEALTH / SD_STUCK / USB_LATENCY_TAIL）。
本报告修正了 `docs/02-IO增强/README.md` 中"12 个事件 ID（1~3 预留 + 5~13）"的过时表述
（该表述漏计 A/C 两线新增的 14~17）。
