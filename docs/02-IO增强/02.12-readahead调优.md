# 块层 readahead 调优（mmcblk0）

> 层级：init（root）/ 验收 ｜ 验收 case：`case:readahead`（`lciod_check.sh --mode readahead`）
> 属性：`persist.lechao.readahead_kb`（缺省 `512` 目标态，置 `128` 回退原厂值）
> 安全边界：**仅写块层队列参数（可逆）**，非块设备裸写，无内核/C++ 改动

## 1. 背景与目标

RPi5 Android 的系统盘 `/dev/block/mmcblk0` 承载 `/data`（ext4）等分区。块层预读窗口
`/sys/block/mmcblk0/queue/read_ahead_kb` 缺省为 **128 KiB**，对顺序读偏保守；适度上调可
减少小读请求次数、提升顺序吞吐。

本批依据 173329 只读 A/B 定标收据
[`data/verify-results/20261016-173329-4834c50fa75a.md`](../../data/verify-results/20261016-173329-4834c50fa75a.md)
将默认预读窗口调整为 **512 KiB**，并以 init 属性 trigger 提供即时生效与可逆回退。

**A/B 实测（173329，`dd` 顺序读 mmcblk0p3 80MB，每档先 `drop_caches`）**：

| `read_ahead_kb` | 均值耗时 | 吞吐 | 相对 128 |
|-----------------|----------|------|----------|
| 128（原厂） | 961.5 ms | 82.9 M/s | — |
| 512 | 909.5 ms | 88.1 M/s | **+6.3%** |
| 1024 | 909.0 ms | 88.1 M/s | +6.3%（无额外增益） |

结论：**512 已饱和，1024 无收益**，故目标态取 512。

## 2. 机制与实现

### 2.1 init 属性 trigger

新增 `device/brcm/rpi5/scripts/rpi5-readahead.rc`（prebuilt_etc 安装到
`/system/etc/init/rpi5-readahead.rc`）：

```
on property:persist.lechao.readahead_kb=512
    write /sys/block/mmcblk0/queue/read_ahead_kb 512

on property:persist.lechao.readahead_kb=128
    write /sys/block/mmcblk0/queue/read_ahead_kb 128
```

- **默认 512**：`vendor.prop` 增加 `persist.lechao.readahead_kb=512`，属性初始化即触发
  首个 trigger，开机即为目标态。
- **即时生效**：`setprop persist.lechao.readahead_kb 512|128` 改变属性即触发对应 trigger，
  无需重启。
- **可逆回退**：置 `128` 写回原厂默认；持久属性落 `/data/property`，重启后仍按该值生效。
- **部署**：`scripts/Android.bp` 新增 `prebuilt_etc rpi5_readahead_rc`；`device.mk` 的
  `PRODUCT_PACKAGES` 登记；`verify-cases.yaml` 的 `lciod.targets/push` 同步登记，保证
  编译产物与上板推送一致。

### 2.2 安全边界

| 项 | 说明 |
|----|------|
| 写对象 | 仅 `/sys/block/mmcblk0/queue/read_ahead_kb`（块层队列参数，纯内存态） |
| 可逆性 | `setprop persist.lechao.readahead_kb 128` 即时恢复原厂值 |
| 数据面 | 无块设备裸写、无 `dd` 写、不触碰分区数据 |
| 代码面 | 无内核改动、无 C++ 改动，仅 init rc + 属性 + 验收脚本 |

> 属性值仅接受 rc 显式声明的 `512`/`128` 两态；写入其他值不会命中 trigger，sysfs 保持不变。

## 3. 验收

`harness/skills/workspace-verify/cases/lciod_check.py --mode readahead`（case：`readahead`）：

1. **主断言**：读 `/sys/block/mmcblk0/queue/read_ahead_kb`，必须等于 **512**。非 512、
   不可读或非数字均判红（属性 trigger 未生效不得假绿）。
2. **冷启动记录**：`drop_caches` 构造冷缓存后 `am start -W -a android.settings.SETTINGS`，
   解析 `TotalTime` 并与 173329 基线 **757 ms** 对比，打印变化量与百分比。

**板端增量验证口径**：增量推送只更新 `/system/etc/init/rpi5-readahead.rc`，不会更新
已打包的 `vendor/build.prop`，故 case 先执行
`adb shell setprop persist.lechao.readahead_kb 512` 建立目标态（等价 build.prop 默认值），
再由 checker 断言 sysfs 落地。全量刷机后开机即由 build.prop 默认值触发同一 trigger，
无需 setprop。

**冷启动对比口径**：173329 实测设置应用冷缓存启动 `elapsed=756.7 ms`、`am TotalTime=703 ms`、
块层 read sectors Δ=25776（13.2 MB）、read ticks Δ=660 ms。本 case 以 `am TotalTime` 为主
记录值，**仅作跨批趋势对比，不作门禁**——设备间与运行时状态差异较大，门禁以 sysfs=512 为准。

**默认即目标态不复原**：case 结束不写回 128；如需回退，人工执行
`adb shell setprop persist.lechao.readahead_kb 128`。

### 防假绿

| 场景 | 判据 |
|------|------|
| 属性 trigger 未生效 | sysfs ≠ 512 → exit 1 |
| sysfs 不可读 | `cat` rc≠0 → exit 1 |
| 冷启动测量失败 | `am start` rc≠0 → exit 1 |
| 输出缺耗时字段 | 无 `TotalTime`/`WaitTime` → exit 1 |
| adb 超时 | rc=-1 透传，上游判失败 |

## 4. 回退与影响

- **回退**：`setprop persist.lechao.readahead_kb 128`（即时写回 128）；如需彻底移除，
  删除 `vendor.prop` 中的属性并移除 rc 的 `PRODUCT_PACKAGES` 登记后重编。
- **影响面**：仅 mmcblk0 块层预读窗口；对随机读无显著影响，顺序读吞吐提升约 6.3%
  （173329 定标）。
- **可观测**：`adb shell getprop persist.lechao.readahead_kb` 与
  `adb shell cat /sys/block/mmcblk0/queue/read_ahead_kb` 可直接核对属性与实际生效值。
