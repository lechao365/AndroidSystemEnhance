# ext4 存储清理链（FITRIM）

> 层级：用户态 (system) / 验收 ｜ 事件 ID：`LCVIEW_EVENT_TRIM` = **20**
> 验收 case：`case:trim`（`lciod_check.sh --mode trim`）
> 开关：`sys.lechao.lciod.trim_enable`（缺省 `0`，关闭即零动作）
> 安全边界：**仅 FITRIM 释放文件系统空闲块（无损）**，禁块设备裸写（`BLKDISCARD`）与 `dd`

## 1. 背景与目标

RPi5 Android 的 `/data` 为 ext4 分区（`/dev/block/mmcblk0p3`），长期读写后空闲块碎片化会推高
新分配延迟。ext4 提供 `FITRIM` ioctl 让文件系统在**只释放空闲块、不触碰已分配数据**的前提下向
底层块设备下发 `discard`，由 eMMC/SD 的擦除策略回收，从而维持空闲块连续性。

本批（UP-110 批一）在 lciod daemon 内落地 **TrimManager**：按开关 + 空闲率/天数决策，自盘尾向
前**分段** FITRIM，度量块层 `discard` 差分并落事件（id=20），构成「决策 → 执行 → 度量 → 上报」
清理链闭环。

**环境基线**（前批只读核查收据
[`data/verify-results/20261016-114849-2273dbaffa09.md`](../../data/verify-results/20261016-114849-2273dbaffa09.md)）：

| 项 | 实测 |
|----|------|
| `/data` 文件系统 | ext4，挂载选项 `rw,seclabel,nosuid,nodev,noatime,errors=panic` |
| 设备节点 | `/dev/block/mmcblk0p3`；块层统计 `/sys/block/mmcblk0/stat` |
| fstrim 历史 | **从未执行**（logcat 0 条、无 `last-fstrim`、`stat` discard 字段全 0） |
| deviceidle Doze | 关闭（`mDeepEnabled=false`），系统级 fstrim 未接管 |

> 该基线是决策阈值与「首次清理」语义的参数来源，且要求随批入 git（ENV-BASE-001）。

## 2. 机制与安全边界

- **FITRIM 语义**：`ioctl(mount_fd, FITRIM, &fstrim_range{start,len,minlen})`。内核在 ext4 上
  只对 `[start, start+len)` 内**空闲** extent 下发 trim，不动已分配数据 —— 无损、可中断。
- **不裸写块设备**：不使用 `BLKDISCARD`（其按物理块丢弃，不感知文件系统占用），不使用 `dd`。
- **缺省关闭**：`sys.lechao.lciod.trim_enable` 缺省 `0`，未开启时运行循环 `continue`，零动作。
- **禁用 vold 路径**：状态写 lciod 自持路径 `/data/misc/lechao/lciod/trim-state`，**禁碰**
  `/data/misc/vold/last-fstrim`（避免与 vold 生命周期/标签冲突）。

### FITRIM ABI 与权限

按本仓 `hal/vendor_lechao_usbd-ioctl.h` 先例**手工声明内核 ABI**（避免 `<linux/fs.h>` 与
bionic 头冲突）：

```c
struct lechao_fstrim_range { uint64_t start, len, minlen; };
#define FITRIM _IOWR('X', 121, struct lechao_fstrim_range)  /* = 0xC0185879 */
```

ext4 `ext4_ioctl` 的 FITRIM 分支**前置 `capable(CAP_SYS_ADMIN)`**。daemon 以 `system`(UID 1000)
运行、`CapEff=0`，故：

- `daemon/lechao_lciod.rc`：新增 `capabilities SYS_ADMIN`（init 授予，仅按开关触发）；
- `sepolicy/lechao_lciod.te`：`allow lechao_lciod self:capability sys_admin;` +
  `/data` 挂载点目录（`system_data_root_file`）`dir { open read search getattr ioctl }` +
  自持状态（`system_data_file`）目录/文件写权限。

## 3. 决策与执行

### 决策（纯函数 `ShouldTrim`）

```
eligible = enabled && ( drill
                      || never_trimmed
                      || ( free_ratio_bp >= kTrimFreeThresholdBp
                           && days_since_last >= kTrimMinDays ) )
```

| 参数 | 值 | 理由 |
|------|----|------|
| `kTrimFreeThresholdBp` | 5000（50%） | 空闲占比高时收益大、耗时可控；数据密集时收益有限易拖慢 IO |
| `kTrimMinDays` | 7 | FITRIM 占块层队列，一周一次足以维持空闲块连续性 |
| `never_trimmed` | 首清无门槛 | 基线显示从未 trim，首次直接放行 |
| `drill` | `trim_drill` 钩子 | 值变化一次性（仿 `zram_swap_drill`），绕过阈值便于单段测试 |

### 执行（`ExecuteSegmentedTrim`）

- 打开挂载点**目录 fd**（`O_RDONLY|O_DIRECTORY`），**自盘尾向前**按 `kTrimSegmentBytes`＝32MiB
  分段 FITRIM（`SegmentAtFromTail`：`start = tail - seg`，末段可更短）；
- 段间 `usleep(kTrimSegmentSleepUs=5000)` 给块层队列喘息；
- **熔断**：耗时 ≥ `kTrimBudgetMs`(300s) 或段数 ≥ `kTrimMaxSegments`(8192) 即安全退出
  （`circuit_breaker=true`，已执行段保留）；
- 单段瞬时失败（`EINTR`/`EIO`）记录后继续；`EOPNOTSUPP`/`ENOTTY`/`ENOSYS`（不支持 discard）
  判致命退出（`error` 带原因，不吞错，CXX-002）。

### 度量

执行前后各读 `/sys/block/mmcblk0/stat`，对第 11~14 字段（`time_in_queue` / `discard_ios` /
`discard_merges` / `discard_sectors`）做差分，随事件上报——`discard_ios` 严格递增即 FITRIM 真实
经块层下发 `discard` 的**硬证据**。

## 4. 事件与落盘

新增事件 **id=20** `trim`（三镜像 1:1 同步）：

| 位置 | 文件 |
|------|------|
| 内核真相源 | `code/rpi5/kernel/new/vendor/lechao/LcView/lcview_events.h` |
| AOSP 镜像头 | `code/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/include/lcview_events.h` |
| schema | `code/rpi5/aosp/new/vendor/lechao/services/lechao_lcview/config/lcview_events.json` |

字段：`trimmed_bytes` / `segments` / `duration_ms` / `free_ratio_bp` / `discard_ios_delta` /
`discard_sectors_delta` / `time_queue_delta_ms`。

该事件为 **daemon 合成**（无内核发射点），故在 `harness/lib/check_lcview_events.py` 的
`DISABLED_EVENTS` 登记豁免（与 `slow_disk`=14 / `usb_latency_tail`=17 /
`zram_swap_pressure`=19 同口径）。daemon 经专属 tag `lechao_lciod_event` 落 JSON 行
`{"rule":"trim", ...}`。

## 5. 验收

`harness/skills/workspace-verify/cases/lciod_check.py --mode trim`（case：`trim`）：

1. 开 `trim_enable=1` + 单段演练 `trim_drill=1`（每轮置 `0`→`1` 保证重新触发）；
2. 断言 `/sys/block/mmcblk0/stat` `discard I/Os` **严格递增**；
3. 断言 logcat tag `lechao_lciod_event` 出现 `"rule":"trim"`。

防假绿：开关未生效 / discard 未递增 / 无事件留痕均判红。`teardown`（YAML `setup_snapshot` +
`teardown`）复原两个 sysprop；`timeout_s=240`（含 daemon 10s 决策窗与轮询）。

## 6. 单测

`tests/TrimManager_test.cpp`（纳入 `lechao_lciod_unit_test`）覆盖：

- 纯函数：`ComputeFreeRatioBp`（除零/超 100% 钳制）、`ShouldTrim`（阈值/天数边界、drill、
  never_trimmed）、`SegmentCount`（ceil/零）、`SegmentAtFromTail`（尾段满/首段不满/越界/零）、
  `CircuitBreakerTripped`（时间/段上限边界）；
- 执行层 I/O：`StatMount` 取值、`ReadState`/`WriteState` 状态文件往返与
  **非法内容拒绝**（CXX-003）、缺文件 → `never_trimmed`。

`ExecuteSegmentedTrim` 依赖真实挂载点 FITRIM（系统态），交由板端 `--mode trim` 闭环验证。
