# sync-patchs-to-doc 防漂移增强设计

> **版本**：v2（2026-06-17）
> **前置版本**：[2026-06-15-sync-patchs-to-doc-design.md](./2026-06-15-sync-patchs-to-doc-design.md)（初版，定义同步链路骨架）
> **本次目标**：解决"找到变更文件但不会更新文档"问题，将代码 diff 精准转换为文档更新，防止 AI 自由发挥导致的细节漂移。

## 背景与问题

`sync-patchs-to-doc`（初版）只负责"找变更文件 + 分发到文档目录"，但**"如何更新文档内容"完全没有规范**。AI 拿到 diff 后自由发挥，导致四类漂移：

1. **章节结构漂移**：不遵守模板 4+1 视图骨架
2. **代码路径写错**：写成 workspace 路径而非 patchs 相对路径
3. **行号锚点失效**：源码改动后不更新 `#L248`
4. **风格不一致**：表格/图/代码块混用比例失控

## 设计决策（brainstorming 确认结果）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 能力载体形式 | **吸收合并到 sync-patchs-to-doc** | update-doc 强依赖 sync 的输出（diff+manifest）且仅被它使用，分离增加传递成本 |
| 命名 | 统一用 `sync-patchs-to-doc` | 不保留 update-doc 命名 |
| 触发方式 | 由 `/sync-patchs-to-doc` 命令内部闭环 | 单命令完成"找+取上下文+定位+出方案+落盘+自检" |
| 上下文来源 | manifest.yaml → workspace 全量源码 | patchs 的 modified 类只有 diff 无上下文，需 manifest 桥接 |
| 更新粒度 | **章节级增量** | 禁止全文重写，仅改受影响章节 |
| 变更→章节映射 | **行号锚点 + 符号名** | 确定性查找，不靠 AI 凭空判断 |
| 可更新范围 | 模板只读，文档可改；模板冲突须确认 | 模板是契约，防结构漂移 |
| 交叉引用 | 代码引用自动维护 | 文件矩阵/路径链接/行号锚点自动更新 |
| 行号锚点 | 重新定位并刷新 | 保证锚点始终有效 |
| 方案粒度 | 动作清单级 | 文档→章节→动作，确认后再生文 |
| 落盘后验证 | 自动一致性检查 | 防止引入新问题 |

## 架构：单 skill 7 步闭环

```
/sync-patchs-to-doc [--full-diff]
   ├─① 找变更   git diff HEAD -- patchs/rpi5 → 变更清单 + diff 正文
   ├─② 分发     rules/doc-sync-mapping.md → 受影响文档目录（01/02）
   ├─③ 取上下文 读 manifest.yaml → 去 ~/workspace/ 读全量源码（精准，无盲搜）
   ├─④ 定位章节 行号锚点(#Lxxx) + 符号名 + 文件名 → 受影响文档章节（5 形态 3 定位法）
   ├─⑤ 出方案   动作清单级方案（文档→章节→动作）→ 用户确认
   │            ⚠ diff 与模板冲突 → TEMPLATE-CONFLICT，确认后才动模板
   ├─⑥ 落盘     章节级增量改文档（严守模板 4+1 视图）；刷新行号锚点（含形态 D 盲区）
   └─⑦ 自检     自动一致性检查 → 输出报告
```

## 防漂移四大支柱

| 支柱 | 规则 |
|------|------|
| **模板只读** | `templates/*.md` 是契约。AI 不得自行改模板；冲突时停下让用户确认 |
| **章节级增量** | 仅改受影响章节，禁止全文重写；新增内容只能加到模板现有章节 |
| **代码引用规范** | 代码路径走 `patchs/` 相对路径 + `#L行号`，禁 workspace 路径；刷新含形态 D 盲区 |
| **内容对齐 diff** | 描述基于真实 diff/workspace，禁臆造接口/字段/行为 |

## diff → 文档更新转换机制（核心）

### 文档引用代码的 5 种形态

| 形态 | 格式 | 盲区风险 |
|------|------|---------|
| A 行号锚点链接 | `[file:行](路径#L行)` | 中 |
| B 文件路径链接 | `` [`file`](路径) `` | 低 |
| C 纯文本文件名 | 正文叙述 | 高 |
| D 代码块注释 | `// file:行`（块内）| **极高（链接检查器盲区）** |
| E 文件矩阵 | 目录树/表格行数列 | 中 |

### 三种定位法（对每个变更点组合使用）

```
【符号名】  rg "<symbol>" 01-*/02-*/*.md
【行号锚点】rg "<filename>[:#]L?\d+" *.md  +  rg "^//\s*<filename>:\d+" *.md（形态D盲区）
【文件名】  rg "<filename>" *.md
```

> 关键：同一行号/符号可能在文档中重复出现（职责矩阵 + 不量表 + 关键设计各一次），必须全量命中。

### 变更分类 → 影响范围

| 源码改动类型 | 影响形态 |
|-------------|---------|
| 函数签名变化 | A + 接口参考表 |
| 结构体/字段变化 | 协议表 + 二进制布局图 + ABI映射表 |
| 行数漂移 | A + D |
| 新增文件 | E |
| 文件删除/重命名 | A + B + E |
| 常量/配置变化 | 配置常量表 + 不量表 |

### 动作类型

`UPDATE-锚点` / `UPDATE-表格` / `UPDATE-图` / `UPDATE-文本` / `ADD-文件` / `REMOVE-文件` / `TEMPLATE-CONFLICT`（须确认）。

### 行号锚点刷新机制

对受影响文件的每个被引符号：重新 grep 源码取新行号 → 全量替换文档 `#L旧` → `#L新`（含形态 D 代码块注释、区间引用终点、重复出现处）。
