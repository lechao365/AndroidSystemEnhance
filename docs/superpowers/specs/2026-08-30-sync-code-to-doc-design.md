# sync-code-to-doc 模块生命周期增强设计

- 日期：2026-08-30
- 状态：待评审
- 范围：增强 `harness/skills/sync-code-to-doc/`（SKILL.md + sync_code_to_doc.py），使其支持**结构性重构**（模块删除/迁移）的文档同步；不改变既有章节级增量更新契约

## 1. 背景与目标

### 1.1 现状问题（调查实证）

lcview 已完成去 HAL 重构（dev 相对 main 累计 40 个文件变动），但 `sync-code-to-doc` 现有能力只覆盖"章节级增量更新"，其核心假设是**文档既有章节结构是受控结构**，对结构性重构存在 3 个缺口：

| # | 缺口 | 证据 |
|---|------|------|
| G1 | 无"整篇文档废弃/删除"动作类型 | `docs/01-打点增强/01.02-HAL增强-lcview-hal.md`（87 处 HAL 引用）描述的 `lechao_lcview_hal` 服务被整体删除（hal/ 目录、AIDL、sepolicy、rc 同批 D），skill 只有 `REMOVE-文件`（文件矩阵/目录树），无整篇文档删除动作 |
| G2 | 无"跨文档内容迁移"动作类型 | `hal/DeviceReader.cpp/h → daemon/` 重命名迁移，其模块分解/职责矩阵需从 01.02 迁入 01.03，skill 的 `REMOVE-文件`+`UPDATE-文本` 拼装易漏 |
| G3 | README 索引不纳入，但文档删除后必须同步 | skill 明确"README 映射表不纳入本流程"；删除 01.02 后 `docs/01-打点增强/README.md` 的 01.02 条目、`lechao_lcview_hal` 架构图组件、链路描述全部失效，留下死索引+断链 |

另有**语义失效**风险：重构导致章节语义失效（如 01.03 的"HAL 服务未就绪 / Binder 连接中断 / HAL 服务重试"），非行号漂移，需整段重写，现有流程无显式确认机制。

### 1.2 目标

1. 形成通用的**模块生命周期**能力：模块新增（ADD-DOC）/ 删除（REMOVE-DOC）/ 迁移（MIGRATE-内容）/ 演进（现有增量机制）
2. README 索引兜底：文档结构变化时强制同步索引，日常增量文本更新仍不纳入
3. 语义失效章节重写显式化：列入动作清单由用户确认
4. 脚本增加文档索引一致性检查（`--check-docs`），落盘后闭环验证
5. 本次 lcview 去 HAL 重构可用增强后的 skill 生成正确文档

## 2. 设计

### 2.1 新动作类型（SKILL.md §5.2 扩展）

| 动作类型 | 说明 | 确认级别 |
|---------|------|---------|
| `REMOVE-DOC` | 整篇删除文档：删除文件 + README 索引清理 + 全仓交叉引用清理 + 断链自检 | **强制确认**（同 DOC-CONFLICT） |
| `RENAME-DOC` | 文档重命名/重编号（如 01.03→01.02）：改名文件 + README 索引更新 + 全仓交叉引用清理 + 文档内编号/标题同步 + 断链自检 | **强制确认**（同 DOC-CONFLICT） |
| `MIGRATE-内容` | 跨文档章节/文件引用迁移（源→目标），如 DeviceReader 01.02→01.03 | **强制确认** |
| `REMOVE-文件`（现有） | 文件矩阵/目录树移除 | 常规 |

`REMOVE-DOC` 删除的文档**不额外归档**：git 历史已保留内容，追溯用 `git log`/`git show`。

### 2.2 文档级影响判定（Step 4 前置，新增判定逻辑）

对 diff 先做**文档级影响判定**，区分"结构性变化"与"增量变化"：

| 判定信号 | 文档级影响 | 动作 |
|---------|-----------|------|
| 服务目录整删（`hal/`、`aidl_api/`、`*-service.xml`、`*.rc`、sepolicy `*_hal.te` 同批删除） | 模块消失 | `REMOVE-DOC` |
| 文件重命名跨目录（`hal/DeviceReader.cpp → daemon/`） | 内容归属变更 | `MIGRATE-内容` |
| `REMOVE-DOC` 造成编号空缺需重排（如 01.02 删除后 01.03→01.02）；或用户指定改名/主题变更 | 文档编号/名称变更 | `RENAME-DOC` |
| 单文件行号漂移/签名变化/常量变化 | 无 | 现有增量机制（UPDATE-锚点/表格/图/文本） |

判定依据：diff 状态（A/M/D/R）+ 路径模式 + 同批删除关联性（目录+service.xml+rc+sepolicy 同时 D = 服务不存在）。

### 2.3 README 兜底规则（修改"不涉及的文档"）

原规则"README.md 映射表更新不纳入本流程"改为条件化：

- **触发**：文档结构变化时（`REMOVE-DOC` / `ADD-DOC` / `RENAME-DOC`）强制同步 README 索引——文档列表条目、架构图组件、链路描述
- **不触发**：日常增量文本更新（章节级 UPDATE 动作不涉及 README）

### 2.4 语义失效章节重写（Step 5.2 扩展）

架构变化导致章节语义失效时，整段重写**仍属 `UPDATE-文本`**，但必须：
- 在动作清单中显式标注"语义重写"及失效原因（如"HAL 服务未就绪 → 设备节点直读失败"）
- 列入动作清单由用户确认（与 DOC-CONFLICT 同级确认门）

### 2.5 脚本增强（sync_code_to_doc.py）

新增 `--check-docs` 参数，输出文档索引一致性报告：

| 检查项 | 方法 | 输出 |
|--------|------|------|
| 死索引 | README 索引条目（表格行/列表项）指向 docs/ 下不存在的文件 | 列多余条目 |
| 漏索引 | docs/ 下存在文件但 README 无对应条目 | 列缺失条目 |
| 断链 | 全仓 markdown `](./xxx.md)` 交叉引用目标不存在 | 列断链（源文件+链接） |
| 孤儿 | docs/ 下无任何入链的文档（REMOVE-DOC 后检测残留引用） | 列孤儿文档 |

退出码：0=一致；5=发现不一致（供落盘后自检判定）。

### 2.6 流程调整汇总（SKILL.md）

- Step 4：新增"文档级影响判定"（§2.2）
- Step 5：动作清单增加 `REMOVE-DOC` / `MIGRATE-内容`，语义重写显式标注（§2.4）
- Step 6：`REMOVE-DOC` 后执行 README 兜底（§2.3）
- Step 7：自检增加 `--check-docs` 索引一致性（§2.5）

## 3. 本次 lcview 场景验证路径

1. 报告：`--base origin/main`（40 文件变动，现有脚本已覆盖）
2. 文档级判定：`hal/` 整删 + AIDL/rc/sepolicy 同批 D → `REMOVE-DOC(01.02)`
3. DeviceReader 迁移：`hal/ → daemon/` → `MIGRATE-内容(01.02→01.03)`
4. 01.03 语义重写："HAL 服务未就绪"→"设备节点直读失败"、"Binder 连接中断"→"直读失败重试"等，列动作清单确认
5. 01.01 内核文档 HAL 引用清理（10 处）
6. README 索引同步：删 01.02 条目、改架构图组件与链路描述
7. `--check-docs` 自检：断链/死索引/孤儿全绿

## 4. 兼容性

- 既有章节级增量更新契约不变（默认只更新文档不动结构）
- 现有动作类型（UPDATE-*/ADD-*/REMOVE-文件/DOC-CONFLICT）语义不变
- 脚本现有参数（`--base`/`--full-diff`/`--check-only`）行为不变，`--check-docs` 为增量能力
- 文档删除后一致性自检的"交叉引用可达"检查天然覆盖 REMOVE-DOC 遗留断链

## 5. 不做的事

- 不引入自动删档：`REMOVE-DOC` / `MIGRATE-内容` 一律强制用户确认
- 不新增归档目录（git 历史即归档）
- 不改 README 日常更新规则（仅文档结构变化时兜底）
- 不改变 `code/rpi5/README.md` 映射表维护方式（仍不纳入）
