## body

- 现场: rpi-zero2w usb-fault-inject 的 expect.c 经 expect_output_by_id() 输出 `{"fault":"<name>","expect":{"kernel_event":<n>,"<count>":<n>...}}` 单行 JSON（本批补入 kernel_event 数值字段），契约定位是「供 fault-verify --expect 解析」。但 rpi5 侧 usb-verify（code/rpi5/others/usb-verify）用自有 --expect-event（cli/parse.c:191 解析 event 类型）与 event_check.c 按 event_type 匹配，并不消费 usb-fault-inject 输出的 expect JSON——两侧期望值契约未打通，kernel_event/计数期望不会自动被 rpi5 校验。
- 缺陷归属: KIR-001 回退验证——expect JSON 输出为 usb-fault-inject 既有行为，非本批新增；rpi5 未消费属跨设备（rpi-zero2w 注入器 vs rpi5 校验器）边界契约缺口，缺陷本体不随本批改动消失，不命中 KIR-001~003，按登记处理。
- 影响: fault-verify 无法自动读取注入器声明的期望值，需人工从 stdout 抄录/对齐；kernel_event 枚举或计数期望漂移时 rpi5 校验不会判红，跨边界语义一致性无自动化保障（P1 跨边界）。
- 修法方向: rpi5 usb-verify 侧新增消费该 JSON 的输入通道（--expect-json 或共享契约文件），把 expect 对象与 --expect-event/event_check 语义对齐；属跨设备改动，需单独批次。
- 闭环: 已闭环。usb-verify 新增 `--expect-json <path>` 消费通道（code/rpi5/others/usb-verify/src/cli/expect_json.{c,h}），解析注入器 expect JSON：kernel_event → cmd->expect_event_type（数值与 VENDOR_LECHAO_USBD_EVENT_* 0..6 一致），error/reset/stall/corrupt/timeout_count → 对应 *_ge（-1 不设、>=0 设），命令行显式阈值优先、JSON 只填空缺；文件不可读/JSON 非法/字段越界/缺 fault|expect|kernel_event 均按 FV_ERR_ARGS 判失败。补 host 单测 6 组（tests/fv_pure_host_test.c），`make test` 全过。本批 CDP 批次修复，提交后由 promote 归档回填正式 commit。
