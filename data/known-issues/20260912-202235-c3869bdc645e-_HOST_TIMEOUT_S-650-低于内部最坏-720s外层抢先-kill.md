## body

- 方向5: _HOST_TIMEOUT_S 650 低于内部最坏 720s，外层抢先 kill 丢内层归因。
- 定位: harness/lib/selfcheck.py:123（_HOST_TIMEOUT_S = 650）、:775-776（host 收口 _collect_cmd timeout=_HOST_TIMEOUT_S）；harness/lib/check_host_tests.py:75（单模块 make test timeout=300）、:82（make clean timeout=60）；harness/lib/tests/test_selfcheck.py:303（断言 _HOST_TIMEOUT_S == 650 固化该值）。
- 证据: 内部两模块（LcView/LcIod）顺序跑最坏耗时 = make test 300×2 + make clean 60×2 = 720s；外层 _HOST_TIMEOUT_S=650 < 720，最坏场景下外层 650s 抢先 kill 进程，check_host_tests 内层 TimeoutExpired（300s，归因行"make test 超时（>300s，<module>）"）未及输出即被截断，host_rc=124 只有外层超时标记、无内层模块级归因。test_selfcheck.py:303 断言把 650 固化，反向阻碍修正。
- 影响: host 收口超时场景丢失内层归因（哪一模块、make test 还是 clean 超时），诊断链断。
- 修法方向: _HOST_TIMEOUT_S 提到 ≥ 720（2×300+2×60）+ 缓冲（如 780），并同步改 test_selfcheck.py:303 断言。
