## body

- 现场: harness/lib/content_tree.py:62 先 read-tree {ref}^{tree} 建 ref 树索引，:71 无条件 add -A 把工作树全量加入索引（含未跟踪文件）覆盖 read-tree 结果，:75 write-tree 输出工作树快照而非 ref 树。实测本批 HEAD/HEAD^/HEAD^^/HEAD^^^ 四个不同提交 `content_tree --tree` 均返回同一 hash 033997842e4544a90dbcb4250e53842d50a1ef06（=HEAD 工作树树）。
- 缺陷归属: KIR-001 回退验证——content_tree.py 非本批改动路径，缺陷 pre-existing 历史遗留，非本批引入；不阻塞本批（本批发布被拒因越界提交 e263c6c，与本题无关）。
- 影响: --tree ref 在 ref!=HEAD 或工作树脏时树计算失真，promote 树等价断言（dev HEAD^{tree} vs board verified_tree）依赖该模块，若工作树不净会导致发布内容≠验证内容却返同一 hash 假绿。
- 修法方向: read-tree 后禁止无条件 add -A 覆盖，改为仅对 ref 树与工作树做受控合并（如 git diff-index --cached 校验工作树与 ref 树差异后再决定是否纳入）。
