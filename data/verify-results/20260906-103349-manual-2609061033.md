# LCV-03/04/05：输出合法性与丢数据可见性（lcview daemon）

## 问题
- LCV-03（P2）：batch_parser bad length 分支 break 后不计数、不推进 offset——剩余批次静默丢弃且心跳 invalid_records 不增长；且 break 后落入 trailing 分支对同段数据重复 writeInvalid（重复落盘缺陷）。
- LCV-04（P2）：FLOAT 字段 NaN/Inf 默认输出 "nan"/"inf"，非合法 JSON 数值，严格解析器整行抛异常。
- LCV-05（P2）：jsonEscapeString 对 >=0x80 字节原样透传，USB 描述符（设备固件来源）可含非法 UTF-8 字节，json.loads 对坏行直接抛异常，一行污染整文件分析。

## 修复
- batch_parser.cpp：bad length 分支补 invalidCnt++ + 丢弃字节数日志，并改为直接 return（writeInvalid 已覆盖 offset 到批尾全部字节，避免 trailing 分支重复落盘/重复计数）。
- FileWriter.cpp：FLOAT NaN/Inf 降级输出 null（std::isnan/isinf，#include <cmath>）；jsonEscapeString 对 >=0x80 字节做 UTF-8 合法性校验（utf8SeqLen：C2-DF/E0-EC/EE-EF/ED/F0-F4 全分支含 overlong 与 surrogate 排除），合法序列直传、非法字节 \u00XX 转义。
