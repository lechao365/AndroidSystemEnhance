## 方向 1 — conserve v3 恢复守恒（直读双端增量，免疫 daemon 重启）
- **v2 缺陷**：只查 ring 空 + HAL buffered 0B 两处积压，不再比较"产生 vs 落盘"；
  六条 DROP 静默时两处皆空反而判绿，真丢记录无法发现。
- **v3 实现**（lcview_check.py mode_conserve 重写）：两拍直读采样（间隔
  `--conserve-sample-s` 默认 5s）：
  - `produced = Δtotal - Δoverrun`（sysfs 直读 `/sys/class/lcview/.../lcview_stats`，
    内核累计，daemon 重启不归零）
  - `landed = ΔJSONL 行数`（`wc -l` 磁盘持久，不受进程内 jsonl_records 归零影响）
  - `in_flight = produced - landed`；`> --in-flight`（默认 16）或 `< -16` 判红
- 删除 v2 的 latest_heartbeats / latest_hal_beat_buffered / kernel_ring_usage；
  kernel_stats() 返回 (total, overrun, ring_usage_bytes)，kernel_total() 复用。
- FakeAdb 加 sysfs_seq / wc_seq 顺序采样支持；TestModeConserve 重写 8 例；
  test_lcview_check.py 58 passed。
- **真机**：`--mode conserve` 窗口 5s 内产生=0 落盘=0 在途=0 OK。

## 方向 2 — FileWriter 六条 DROP 路径计数进心跳
- FileWriter.h 加 `DropCounters` 结构（openFailed / formatEmpty / formatOob /
  reopenFailed / retryFailed / invalidNotOpen）+ `dropCounters()` getter；
  FileWriter.cpp 六条 DROP 路径各自 `++`（L251 LCVIEW_NEED 宏 formatOob、
  L337 openFailed、L345 formatEmpty、L362 reopenFailed、L368 retryFailed、
  L388 invalidNotOpen）。
- daemon 心跳新增 `drop_open= drop_format= drop_oob= drop_reopen= drop_retry=
  drop_invalid=` 六字段——守恒判红后可精确定位丢在哪一条。
- **产品修复（设备真跑暴露）**：writeRecord 原只查 `<< line` 的 fail()，
  ofstream 缓冲未满时 `<<` 不落盘不设 failbit（/dev/full 写 60B 实测 fail()=0），
  flush 失败被漏检且失败后 failbit 粘滞（CXX-002 场景）；改为 `<< line; flush()`
  后统一检查 fail，flush 失败也进恢复路径（clear → reopen → retry → 再 flush），
  retry 失败才 DROP。
- 测试：OpenFileFails_Drops / RetryWriteFails_Drops 补 drop 计数断言 +
  FileWriterDropCountTest 3 例（FormatOob / BadData / InvalidNotOpen）。
- **真机**：新 daemon 心跳实测 `drop_open=0 drop_format=0 ... drop_invalid=0` 六字段在。
